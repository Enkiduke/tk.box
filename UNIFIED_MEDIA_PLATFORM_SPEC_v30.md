## 1. Product Vision

Build a remotely accessible, self-hosted web application that combines:

1. **Plex media library and player:** Browse, search, and play movies and TV episodes stored on authorized Plex Media Servers using a simple, polished interface.
2. **Independent IPTV integration:** Import and play IPTV channels from provider playlists or APIs without routing them through Plex's Live TV functionality.
3. **Custom 24/7 linear channels:** Assemble Plex movies/episodes into TV-style channels with persistent broadcast schedules, a guide, and the ability for viewers to join at the current point in the program, pause privately, resume behind live, or jump back to the live broadcast.

A user must experience these as **one application, one account/session, one player, and one coherent design system**. The backend may use separate modules for different media sources, but the UI should not expose their implementation details.

### 1.1 Core promises

- Simple onboarding; fast, clean library browsing; reliable playback.
- One **Live TV** destination combining IPTV channels and custom Plex-powered channels.
- A **single unified electronic program guide (EPG)** combining provider-supplied XMLTV data with internally generated custom-channel schedules, with **All Channels / IPTV / Custom Channels / Favorites** filters and one admin-managed channel lineup.
- Remote access from desktop/laptop browsers through the owner's existing custom-domain HTTPS reverse proxy, forwarding to an app-selected internal port; native Ubuntu/Debian installation on the existing Plex host.
- No requirement to configure IPTV as a Plex tuner/DVR source.
- Custom-channel tuning, background playback, pause, resume, Go Live and scheduled episode changes never modify Plex movie/episode watch progress, play count or watched state. Intentional on-demand Plex playback continues normal per-viewer sync.
- True 24/7 broadcast timing driven by a persistent server-side schedule, without continuously transcoding channels that have no viewers.
- **CPU-only host; Smart CPU video transcoding is CONFIRMED for eligible 1080p-or-lower media.** Prefer direct play, then stream-copy/remux; fall back to limited software video encoding only when necessary for browser compatibility. Never transcode a 4K HEVC video track. No GPU acceleration is assumed; compatible 4K video may be direct-played.
- **Persistent Live TV mini-player**: IPTV and custom channels continue through in-app page navigation, with one playback instance moving between expanded and docked layouts. This is part of MVP, not a later enhancement.
- **Explicit one-at-a-time playback**: pressing Play on Plex on-demand content terminates any live IPTV or custom-channel session first; the user returns to Live TV only by navigating there and deliberately selecting a channel.
- **Viewer playback quality controls (CONFIRMED):** Auto by default, plus Original, 1080p and 720p where a valid stream is actually available. These selections do not override CPU-encoder admission limits or the 4K HEVC ban.
- **Audio and subtitle behavior (CONFIRMED):** For Plex movies, episodes and custom channels, start with the signed-in viewer's Plex audio/subtitle language and activation preferences. Let that viewer select any accessible compatible audio and subtitle track manually. IPTV starts from provider-selected tracks and exposes only tracks the provider supplies; do not copy Plex preferences to IPTV.
- **Custom-channel track carryover (CONFIRMED):** If a viewer manually chooses audio language or subtitles during a custom-channel session, keep that choice across program transitions in the same session. If the next program lacks a compatible track, temporarily fall back without discarding the viewer's requested language/Off preference. Revert to Plex defaults only when a **new** custom-channel viewing session starts.
- **IPTV disruption recovery (CONFIRMED):** Automatically reconnect when an active M3U live feed unexpectedly disconnects, stalls, or times out, with a small finite retry budget and bounded backoff. Show clear **Reconnecting** feedback; if attempts fail, stop automatic recovery and show a contextual error plus a **manual Retry** button. This **does not** apply to `TRANSCODE_CAPACITY_REACHED`, prohibited codec conversions, deliberate channel switching, or sign-out.
- **IPTV discovery approval (CONFIRMED):** Each M3U playlist independently controls **Auto Add New Channels** in admin Settings; the toggle is **Off by default**. New entries detected while Off go to an administrator-only **Pending Review** list. Only explicitly approved entries become visible/playable in the unified guide. Existing imported channels still refresh normally and retain manual overrides.
- **Missing IPTV channel handling (CONFIRMED):** If a previously approved channel is **absent from a successful, complete, validated M3U refresh**, hide it immediately from the viewer lineup, guide, search and new tuning. Retain its durable identity, favorite associations, manual number/order and admin settings. A fetch failure or incomplete snapshot must never hide it.
- **Returning IPTV channel restoration (CONFIRMED):** When a previously approved missing channel unambiguously reappears in a later valid M3U snapshot for the **same source**, automatically restore the original channel record with its saved number, position, favorites and customizations. **Do not re-enable administrator-disabled/hidden channels** or send a known returning identity to Pending Review. Ambiguous/recycled provider identities require administrator reconciliation before any restoration.
- **IPTV/EPG refresh scheduling (CONFIRMED):** Independently configure the automated refresh cadence for **each M3U playlist** (default **12 hours**) and **each XMLTV feed** (default **6 hours**) in administrator Settings. Provide an explicit administrator-only **Refresh Now** action for either source type. Refresh failures retain the last valid data, never imply disappearance, and do not overwrite saved intervals.
- **Cached XMLTV fallback (CONFIRMED):** When a feed fails to refresh, keep rendering last validated XMLTV listings **only where their real program start/end times cover the requested guide window**. As that coverage runs out, label the uncovered span **No guide data** rather than extending the previous program, inventing a future schedule or concealing a working IPTV channel. No arbitrary data-age cutoff invalidates a still-scheduled cached entry merely because its feed was not refreshed; show diagnostic freshness separately to the administrator.

### 1.2 Non-goals for the first release (PROPOSED)

- No DVR/recording or timeshift for **external IPTV** at launch. Custom Plex-powered channels support bounded viewer-local pause/resume buffering, but no arbitrary DVR recordings or restart-from-beginning feature.
- No Plex Live TV tuner/HDHomeRun emulation requirement.
- No sharing of third-party IPTV account credentials between users.
- No DRM bypassing, geographic restriction circumvention, or unauthorized content redistribution.
- No IPTV video-on-demand, Xtream Codes integration, or Plex Live TV/DVR ingestion in the initial scope.
- No native mobile/TV applications, TV-remote UX, synchronized group watch, or multi-server aggregation in the MVP; desktop/laptop web takes priority. Basic responsive fallback and accessibility are still required.

## 3. Target Users, Authentication, and Deployment

### 3.1 Accounts and permissions (CONFIRMED: Plex Pass owner and pre-shared viewer accounts)

- Users sign in with their **existing Plex accounts**. Intended viewers already have Plex accounts with access shared to this Plex server. Normal users do not need application-specific usernames or passwords.
- Use a Plex-supported account authorization flow such as PIN / browser account linking. Never ask users to type their Plex passwords into this application.
- A successful Plex sign-in establishes **identity, not authorization**. The backend must confirm that the Plex account is the server owner or has explicitly permitted access to this Plex server.
- The Plex server owner has an active **Plex Pass** and is the bootstrap **Administrator** (identified by a stable Plex account ID, not a username or email string). Already-authorized shared Plex accounts are **Viewers** unless intentionally promoted by an administrator.
- **CONFIRMED deployment assumption:** Every intended user has access to **both the Movies and TV Show libraries** on this one Plex server. Channel creators may therefore choose content from either library for a single shared channel. The MVP does not require individual program substitutions, permission-specific alternate schedules, or a per-viewer restricted-content slate as part of normal operation.
- **Security invariant:** Shared library access is not permanent permission to bypass Plex. Validate the identity and current Plex/server/library grants on login and protected playback requests; if a grant is later revoked or content becomes restricted, deny the affected playback request without using the owner's access to override it. The 24/7 schedule remains unchanged for all other authorized viewers.
- Each user receives a separate application session, favorites, preferences, and on-demand watch-progress context. Plex-library visibility and media playback must be checked against that user's approved Plex access rather than silently using the server owner's all-access token.
- Administrators may configure one or more M3U sources and create custom channels. Viewers can browse/play only the sources and channels authorized for them.
- Multiple simultaneous signed-in Plex users are supported. **No blanket application-wide viewer count needs a product decision:** enforce the confirmed app-controlled CPU video encoder budget (default 2, administrator-adjustable), applicable IPTV provider connection limits, and measured disk/network capacity. Direct Play viewers do not consume encoder slots. Set conservative operational guards from Milestone 0 measurements.
- Plex Home managed profiles are **not confirmed** as supported independent sign-in identities in the first release; evaluate only if requested.
- For a Plex authentication outage, existing sessions may remain valid until their normal expiry, but new logins must fail closed. Admin recovery should be a local Linux CLI command, not a remotely accessible master password.

### 3.2 Hosting (CONFIRMED: Ubuntu/Debian, existing reverse proxy + configurable local port)

- Run the application **natively on Ubuntu or Debian, on the same machine as Plex Media Server**. Docker/containers are not required, and no container-based deployment is part of the MVP.
- Connect internally to Plex using a configured loopback endpoint (typically `http://127.0.0.1:32400`) while preserving Plex's normal authentication and server permission checks.
- **CONFIRMED:** The server owner already has infrastructure that maps **custom domains to application ports through an existing HTTPS reverse proxy**. The application only needs to serve HTTP on a configurable internal TCP port; users will map their chosen domain to that port themselves. **Do not install, configure, manage or require a second reverse proxy (Caddy/Nginx) as part of the app.**
- The app binds to a configurable host/IP (`APP_HOST`) and TCP port (`APP_PORT`); **proposed default** `127.0.0.1:3000`. A separate proxy can reach it via a private LAN address or suitable bind with firewall/ACL restrictions. Do not assume the existing proxy shares the same network namespace or that a loopback-only service is always reachable from it. Never expose unauthenticated worker/control ports.
- Install and run as a dedicated non-root Linux service account with a **systemd** unit, persistent state directories, startup on boot, supervised restarts and actionable logs.
- Use the host's installed **software FFmpeg/ffprobe** only. **CONFIRMED:** This server has no GPU transcoding capability. Do not require a running media process for an unwatched virtual channel. Never attempt or silently trigger **4K HEVC video transcoding**, including scaling it to 1080p or another codec.
- The browser communicates with the application over HTTPS and does **not** need access to internal Plex addresses or raw IPTV provider URLs.
- **CONFIRMED host description supplied by owner:** CPU-only; hosting-plan disclosure says CPU PassMark **at least 30,000**, **320 GB RAM**, **40 Gbit/s networking** and datacenter disks. Exact processor model, CPU thread count, disk capacity/available cache space, server uplink throughput, provider throttling, and sustainable concurrent workloads remain **unverified**. Plan/location/availability may change the allocated CPU, so benchmark actual service performance before sizing.
- **CONFIRMED host policy:** 4K streams are permitted to clients with adequate connectivity and codec support, but **4K HEVC video must not be transcoded**. Implement a video-reencode prohibition for any source identified as 4K HEVC, across **Plex VOD, IPTV and custom channels**. Direct play/stream copy of original video may be used where supported; remuxing/container conversion and audio-only conversions must be confirmed as permitted under provider rules and tested before enabling for 4K HEVC.
- The stated **40 Gbit/s network interface is not verified sustained internet egress/uplink or per-user bitrate**; do not infer unlimited remote streams. RAM does not replace measured disk space for retained pause segments. Exact Ubuntu/Debian version, active CPU, disk/storage budget, externally available upload bandwidth, app port, proxy upstream reachability and concurrent stream budget remain **OPEN implementation details**.

### 3.3 Source boundaries (CONFIRMED)

| Source | Used for | Must not be used for |
| --- | --- | --- |
| Plex Media Server | Personal movie/TV library data, artwork, authorized on-demand media playback, source files for scheduled custom channels | IPTV tuner, Plex DVR, third-party live IPTV ingestion |
| M3U provider + XMLTV feed | Import and play **live IPTV channels**; ingest provider-supplied XMLTV schedules, channel IDs and program details | Importing provider VOD, series catalogs, catch-up recordings or playlists into Plex |
| Internal scheduler | Track what every custom station is broadcasting at each real-world instant and publish EPG entries | Requiring 24/7 playback/transcoding jobs when nobody is watching |

The owner has **Plex Pass**. Plex documentation indicates that an admin Plex Pass permits authorized users of that server to stream personal video remotely without requiring each viewer to subscribe separately. The custom-client/API implementation must still validate this behavior with real viewer accounts; reverse-proxying through localhost is not a subscription bypass. [Official Plex remote-playback guidance](https://support.plex.tv/articles/requirements-for-remote-playback-of-personal-media/).

## 4. Information Architecture & Experience

### 4.1 Global navigation (PROPOSED desktop-first structure)

- **Home:** Continue Watching, Recently Added, featured Plex media, Favorite Channels, On Now, scoped to the signed-in Plex account.
- **Movies:** Plex movie libraries with posters, filters, sort, search and details.
- **TV Shows:** Plex show/season/episode navigation, resume and next episode.
- **Live TV (CONFIRMED):** One shared IPTV + custom-channel lineup and EPG; offer exactly four main guide filters: **All Channels**, **IPTV**, **Custom Channels**, and **Favorites**. Default to All Channels. Channel order and display numbers are controlled by an administrator, not by each viewer.
- **Guide (CONFIRMED):** A single desktop-width timeline EPG grid for IPTV XMLTV and generated custom-channel schedules. All filters operate on that same grid/player and never open a second TV interface. Viewers can favorite/unfavorite any visible IPTV or custom channel independently.
- **Search:** One search surface across Plex assets and channel/program metadata, with clear result types.
- **Settings:** Viewer playback preferences; admin-only sections for Plex, IPTV, channels, users and system. Under **Settings → Channels → Playback & Buffering**, administrators can change the server-wide **Maximum Pause Retention** (default **30 minutes**) and inspect buffer usage. Under **Settings → IPTV Sources → [Source]**, independently configure each M3U playlist’s **Refresh Interval** (default **12 hours**) and manually **Refresh Now**; under the corresponding linked/standalone XMLTV feed Settings, configure its own **Refresh Interval** (default **6 hours**) and **Refresh Now**. Show last attempt, last success, next expected check and any refresh error. Viewers cannot change these policies.

### 4.2 Design principles

- Clean, modern, minimal visual language. Rich artwork and recognizable channel logos, but avoid excessive decoration or complex configuration on browsing screens.
- Shared top-level navigation, loading/error states, focus indicators, typography, colors, cards, and player chrome.
- Movie and series views resemble a modern streaming library; live views resemble a lightweight television guide.
- Same poster and title metadata renders consistently whether a Plex item appears in a library card or a custom channel's EPG.
- **CONFIRMED:** Keep both IPTV and custom-channel Live TV playback alive during in-app navigation via a persistent docked mini-player; restoring the full player must not cause retuning or loss of the current viewer-local pause state. This is not browser-level Picture-in-Picture.
- Optimize first for a mouse/keyboard and laptop trackpad. Keyboard accessibility is **MUST**; TV-style remote navigation is not an MVP requirement.
- Dark mode **PROPOSED** as the default, with restrained artwork-led styling; a light theme is optional.
- Primary reference viewport: modern desktop/laptop browsers. Avoid mobile-first navigation and giant touch controls, but allow content to reflow rather than break on narrower screens.

### 4.3 Primary user journeys

**Plex first run:** Visit HTTPS site → select **Sign in with Plex** → authorize through Plex → backend validates access to the configured host Plex server → browse allowed libraries → select title → play → resume later.

**IPTV first run:** Admin signs in with Plex → supplies M3U playlist and XMLTV/EPG URL or file → tests provider connectivity → previews **live** channel discoveries and suggested XMLTV matches → configures **Auto Add New Channels** per playlist (**Off** by default) → approves desired entries from **Pending Review** and resolves unmatched EPG IDs → sets channel numbers/order/logos → watches in the same player. Repeated refreshes update previously approved channels without asking for repeated approval.

**Custom channel first run:** Admin opens **Channel Manager** in this application → creates a channel with name/number/logo → browses/searches authorized Plex Movies and TV Shows **inside our own channel editor** → adds movies, full shows, seasons, or individual episodes to an app-owned ordered program list → reorders/removes entries → previews the looping broadcast timeline → publishes → viewers join the correct live position. No Plex playlist creation, editing, or importing is involved.

### 4.4 Desktop design specification (PROPOSED)

**Navigation and layout**

- At approximately 1280–1920 px wide, use a persistent left or top navigation rail with **Home, Movies, TV Shows, Live TV, Search**, and account/settings access. Use only one persistent primary navigation scheme.
- **Movies / Shows:** generous poster-grid layout, artwork and synopsis in a detail view, prominent Play/Resume, and back-navigation that preserves scroll position. Do not replicate all of Plex's advanced screens.
- **Live TV (CONFIRMED):** Persistent filter strip or segmented controls for **All Channels | IPTV | Custom Channels | Favorites**, a compact channel list and a single program grid with names/numbers/logos and horizontally scrollable blocks. The administrator-only **IPTV Pending Review** view belongs under Settings, never as a public guide filter; unapproved channels are omitted from viewer search, channel APIs and tuning. The shared player may dock above/beside the guide or expand to fullscreen. A selected filter narrows rows only, not stream authorization or the underlying guide timing.
- **Guide:** imported provider channels and custom channels share the same time ruler; currently playing programs show progress and clicking a live entry tunes the channel. Future entries reveal details without implying DVR. **Rows have one stable, administrator-defined order and unique display numbers in every filter**. Favorites is a per-viewer subset of that order, not a separate numbering scheme. Empty filters explain the state and offer a way back to All Channels.
- **Custom channel editor:** simple 3-step admin flow: **Basics → Add & reorder content → Preview & publish**. The entire experience belongs to **this application**, not the Plex web interface. Provide an embedded library picker with **Movies / TV Shows** views, Plex search, show → season → episode navigation, bulk add for entire show/season, and add/remove actions. In the app-owned program list, show the expanded episodes with their order, runtime and any missing-file warnings. Support drag-and-drop, keyboard reorder, preview and explicit Save Draft/Publish. For every whole-show selection, show an **Automatically add new episodes** toggle with a sync status. This specific automation is part of the MVP; advanced calendar scheduling remains out of scope. **Do not display an Import Plex Playlist option**.
- **Player:** same visual chrome for all media, with source-aware controls. Plex VOD supports seek and resume. External IPTV is live-only. A custom channel tunes to its shared clock position and offers **Pause, Resume, and Go Live** for the individual viewer. Show an unambiguous **LIVE** state at the live edge, or a **Behind Live** indicator while delayed. **Quality menu (CONFIRMED): Auto (default), Original, 1080p, 720p, with unsupported choices explained or disabled; a manual change must not silently start prohibited transcoding.** Arbitrary rewind/seek and Restart Episode are not MVP controls.
- **Persistent docked mini-player (CONFIRMED):** When leaving Live TV for Home, Movies, TV Shows, Search or Settings, keep the active live stream running in a non-obstructive corner panel. Offer a visible **Restore** action to return to the expanded player and a **Stop/Close** action to release it. Docking is an in-app layout change, not a stream reload. **Exception:** Playing any Plex on-demand movie or episode ends the live session and removes the dock before VOD begins. Returning to Live TV requires manual navigation and tuning.

### 4.5 Persistent Live TV mini-player behavior (CONFIRMED)

- Mount the live media element/player controller in a persistent application-shell layer, **outside route-specific page components**. React route changes switch the same playback session between `expanded` and `docked`; do not create a second `<video>` element or an additional upstream connection just to dock the view. Preserve volume, muted state, captions and live-channel ID.
- **Entering Live TV / expanding:** Show the same actively playing channel in the full guide/player view without a new tune request or reset. A mini-player Restore control navigates back to Live TV and expands the existing player. Browser fullscreen is an optional display mode, not a separate playback session.
- **Leaving Live TV within the app:** Switch automatically to a fixed, docked mini-player. Keep video and audio running for both IPTV and custom channels, subject to actual browser background/autoplay limitations. The dock must not block page navigation, search fields, key dialogs or primary content; provide compact volume/mute, play/pause when supported, a live/behind-live indicator for custom channels, and visible restore/stop controls.
- **Paused custom channel:** If a viewer paused before leaving Live TV, remain **paused in the dock**, not automatically resume. Preserve the viewer's retained timeline and resume at their paused position. Expose **Go Live** where needed; expiry/low-disk behavior follows the configured viewer-local retention rules. IPTV is live-only, so show no nonfunctional pause button.
- **Channel tuning while docked:** If the UI allows choosing another channel without returning to the guide, replace the current active session with that channel, end the prior upstream stream when unreferenced and reauthorize the requested channel. The dock must never keep a hidden old channel consuming an extra stream.
- **Stop, log out, session expiry:** An explicit Stop/Close control ends live playback, removes the dock and cleans up stream resources. Logging out, account/session revocation and permission removal terminate protected playback. Closing the browser/page eventually releases the stream via server-side stale-session expiry; do not rely solely on browser unload events.
- **Navigation boundaries:** Persistence is guaranteed for **client-side navigation within this application**, not for a page refresh, browser close, external website navigation, system sleep or a lost network connection. On refresh, do not auto-start a protected stream without a supported authenticated user gesture and session validation. Reconnection while a page remains open must recover from the current live timeline (or an eligible retained pause position), never from a stale HLS segment.
- **CONFIRMED one active playback session per browser tab in the MVP:** Starting Plex VOD from Home, Movies, Shows, Search or detail screens must **completely stop** the active `iptv_live` or `custom_linear` session, whether expanded, docked, paused or behind live, before starting `plex_vod`. The mini-player disappears. There is **no** suspend-and-return state, post-VOD Return to Live TV shortcut, auto-retune or simultaneous playback in the same tab. Multiple viewers and tabs remain isolated.
- The mini-player is **not** an external OS/browser Picture-in-Picture feature and should not require the browser's PiP API. Native browser PiP is a potential later enhancement, not MVP.

## 5. Functional Requirements

Each requirement has an identifier for implementation and testing. **MUST** denotes baseline intended product behavior, subject to discovery decisions; **SHOULD** denotes proposed lower-priority enhancement.

### 5.0 Plex account sign-in and access control

- **AUTH-01 MUST:** Make **Sign in with Plex** the normal login method using a supported Plex browser/PIN authorization flow, including secure short-lived tokens/JWT where supported by the selected API approach.
- **AUTH-02 MUST:** Validate the returned Plex account token server-side; map the verified immutable Plex account ID to an internal user record and issue a first-party secure session.
- **AUTH-03 MUST:** Admit the server owner and existing shared Plex accounts **only after** verifying permission to the configured Plex server. A random valid Plex account cannot log in merely because it authenticated with Plex.
- **AUTH-04 MUST:** Bootstrap admin status from the configured Plex server owner's stable identity, not from whichever user logs in first.
- **AUTH-05 MUST:** Enforce roles and per-user Plex permissions on catalog, artwork, on-demand playback and virtual-channel media. All intended viewers currently share full Movies and TV-library access, so custom channels use a common lineup rather than viewer-specific programming. **Still check grants at authorization boundaries:** a revoked or restricted user must not receive media through an administrator token or shared segment cache.
- **AUTH-06 MUST:** Provide sign-out, session invalidation, token revocation/reconnect and safe handling of access changes.
- **AUTH-07 MUST:** Keep IPTV provider credentials administrator-only. Viewers already authorized for the Plex server may see IPTV channels **only under the administrator's configured sharing policy**, subject to provider account terms and concurrent stream limits.
- **AUTH-08 SHOULD:** Use an administrator allowlist/denylist over Plex-linked accounts and provide a local-only recovery CLI.

### 5.1 Plex connection and library

- **PLEX-01 MUST:** Authenticate using an authorized Plex account connection and Plex token; do not collect or store Plex account passwords.
- **PLEX-02 MUST:** Connect to the **one configured Plex server on the same Linux host** and test connectivity, ownership and viewer permissions.
- **PLEX-03 MUST:** Query allowed library sections and index movies, shows, seasons, episodes, posters, backgrounds, summary, dates, duration and stream availability.
- **PLEX-04 MUST:** Browse by library, genre and title; paginate/virtualize large libraries; offer sorting and text search.
- **PLEX-05 MUST (CONFIRMED):** Distinguish per-user `plex_vod` sessions from `custom_linear` and `iptv_live`. Only on-demand sessions may alter Plex per-title watched state, resume offset, play count, last-viewed timestamp or Continue Watching. Channel tuning alone must not mutate those values.
- **PLEX-06 MUST:** Show Continue Watching, playback resume and next-episode actions to the extent supported by authorized Plex APIs.
- **PLEX-07 MUST:** Keep cached metadata current through periodic sync and/or event notifications, including renamed, removed, and newly added media.
- **PLEX-08 MUST:** Handle missing servers, expired authorization, restricted library access and removed files gracefully.
- **PLEX-09 LATER:** Multiple Plex servers/accounts are out of MVP scope. Keep adapters extensible without building multi-server UX now.
- **PLEX-10 SHOULD:** Support collections, recommendations and favorites.
- **PLEX-11 MUST (CONFIRMED):** Resolve available audio/subtitle tracks and the signed-in viewer's **Plex-specific language, subtitle activation and subtitle behavior preferences** using supported authenticated Plex data. Prefer Plex-selected/default streams for that account where the API supplies them; do not use the server owner's preferences as a global substitute. Do not assume all Plex user/profile settings are exposed identically on every Plex version; verify with integration tests.

### 5.2 Plex VOD playback

- **PLAY-01 MUST:** Have a consistent embedded HTML5 player for supported Plex media, IPTV streams and custom channels.
- **PLAY-02 MUST:** For VOD, support play/pause, timeline seek, volume/mute, fullscreen, captions, audio selection where available, loading indication and useful errors.
- **PLAY-03 MUST (CONFIRMED):** Use **Smart CPU playback selection** in this order: (1) Direct Play; (2) stream copy/direct stream/remux when browser-compatible and permitted; (3) **CPU software video transcoding for eligible source video at 1080p or below** when compatibility truly requires it and a transcode slot is available. Re-encoding must never be the default for compatible content. Hard-block any 4K HEVC video re-encode, regardless of requested output resolution; do not attempt software re-encoding for media above 1080p in the MVP. Enforce classification and safety rules server-side before initiating Plex transcode or FFmpeg jobs.
- **PLAY-04 MUST:** Support suitable Plex HLS/transcoded output and/or byte-range based direct streams without exposing permanent Plex tokens in public URLs or browser storage.
- **PLAY-05 MUST (CONFIRMED):** Persist and synchronize playback position and viewed status for **on-demand Plex movies and episodes only**, using the authorized viewer identity. Preserve normal Plex resume behavior after seek, stop and completion. Do not route linear-channel sessions through the VOD history reporter.
- **PLAY-06 MUST:** Clean up Plex transcode sessions, local FFmpeg processes, and bounded timeshift buffers when no active or eligible paused viewers require them; expire abandoned viewer sessions and delete unreferenced segments safely.
- **PLAY-07 MUST (CONFIRMED):** For Plex content, initialize audio and subtitle tracks using the **current authenticated viewer's Plex preferences** and available item tracks, with a manual track picker for supported streams. IPTV playback uses provider-offered audio/subtitle tracks; missing tracks must not be fabricated. Handle codec/container, browser and item-boundary compatibility without transcoding forbidden 4K HEVC video.
- **PLAY-08 MUST (CONFIRMED):** Default all newly created playback sessions to **Auto** quality and offer **Original, 1080p and 720p** manual choices **only when a supported and permitted delivery route exists**. Auto MUST prioritize Direct Play then remux/stream copy, using eligible CPU video transcoding as a final fallback. A requested 1080p/720p profile is a maximum resolution cap, not a guarantee to upscale or transcode content into that exact resolution. Manual quality selection can require a transcode even when Original could Direct Play, but may only start after server-side policy and capacity admission. Never offer a 1080p/720p transcode option for 4K HEVC or other disallowed >1080p source video.
- **PLAY-09 SHOULD:** Offer skip intro/credits only if permitted metadata or markers are available; never fabricate markers.
- **PLAY-10 MUST (CONFIRMED):** Watching custom 24/7 channels never marks any underlying Plex movie or episode watched, partially watched or completed, regardless of the portion viewed, background playback, program transitions, pause/resume or Go Live. Do not modify Plex per-title resume positions, last-viewed timestamps, play counts or VOD Continue Watching.
- **PLAY-11 MUST:** Enforce watch-history isolation in backend session authorization: the immutable playback-session mode `plex_vod` is required to accept/watch-progress writes. Reject `custom_linear` and `iptv_live` on Plex progress/scrobble endpoints; app-local favorites or last-tuned channel data must not appear in Plex title history.
- **PLAY-12 MUST:** Verify on a real Plex server that the selected authorized upstream streaming API route does **not implicitly mutate Plex history** on item completion, even without explicit timeline/scrobble requests. If it does, redesign the integration before shipping; skipping client progress calls alone is insufficient.

### 5.2.0 Viewer playback quality controls (CONFIRMED)

- **QUALITY-01 MUST:** Quality starts at **Auto** for new Plex VOD, imported M3U IPTV and custom linear channel sessions. An individual viewer may open one consistent quality menu offering **Auto, Original, 1080p and 720p** when a permissible stream path exists for that source/session. Manual selection is viewer-local; never changes a channel's shared schedule, another viewer's chosen quality, or the admin's encoder limit.
- **QUALITY-02 MUST:** Interpret **Original** as the best available source-native rendition without **video re-encoding** (direct file/stream or container remux, plus audio conversion when necessary and permitted). If the original codecs cannot play without video re-encoding, explain that Original is unavailable instead of silently transcoding it. Original 4K HEVC works only when the browser/device can directly decode it.
- **QUALITY-03 MUST:** Interpret **1080p** and **720p** as *maximum output-resolution choices*, not mandatory conversions or upscaling. If a source or already available HLS rendition is below the requested ceiling, use that rendition. A compatible existing rendition should be selected before a new encode; do not manufacture a new 1080p stream from 720p material.
- **QUALITY-04 MUST:** Determine available menu options from source probing, actual M3U/HLS variants, browser capability, viewer authorization, streaming protocol, 4K hosting restrictions, and eligibility for at-most-1080p CPU transcoding. Show unavailable options disabled with a short reason, or omit them with an explanatory status; never present controls that cannot work for that stream. Quality options may change when a channel moves to a new item.
- **QUALITY-05 MUST:** Apply manual choices through server-side playback negotiation. For any quality change that would start a new video encoder, require an **atomic permit** under the administrator-configurable global encoder limit (default 2); when full, respond immediately with **TRANSCODE_CAPACITY_REACHED** and an explicit **Retry** action. No request queue, automatic retry, hidden downgrade, or preempting other viewers.
- **QUALITY-06 MUST (HARD SAFETY):** Never video-transcode **4K HEVC**, including requested 1080p/720p output, subtitle burn-in, HDR tone mapping, forced codec changes, or scaling. In MVP, video from any source above 1080p remains ineligible for video re-encoding. Compatible 4K direct play/remux is allowed; otherwise explain the codec/policy incompatibility separately from capacity errors.
- **QUALITY-07 MUST:** Make quality switching safe: obtain/check the candidate stream path *before* stopping the current one where possible; preserve the current movie/episode seek position, or the custom station's current viewer-local paused/behind-live position, when the new path supports it. IPTV must rejoin its current live edge, not invent rewind support. If the requested route cannot start, keep the existing valid stream running and explain why; never turn a quality failure into a needless channel change or VOD restart.
- **QUALITY-08 MUST:** If multiple viewers request different encodings, use separate encoded renditions only when permitted by the global encoder budget; share identical compatible encodes where practical. Switching back to Direct Play/Original must release an encoder permit after the encoded stream is no longer needed. A single user's selection must not change another viewer's rendition or live/paused state.
- **QUALITY-09 MUST:** Preserve authorized Plex VOD progress synchronization through manual/Auto quality changes. Custom channel quality changes must never report Plex watched progress. For MVP, keep manual quality choices within the current playback session and start each new playback session in **Auto**; this is a nonblocking implementation default, not a new user-confirmed persistent preference.
- **QUALITY-10 SHOULD:** Surface the active delivery resolution/route (e.g., `Auto · Original · Direct Play` or `720p · Transcoding`) and give distinguishable errors for unavailable rendition, transcoding capacity, network failure, and provider limits. Include keyboard-friendly, screen-reader-accessible player controls.

### 5.2.1 Persistent player lifecycle requirements (CONFIRMED)

- **PLAY-13 MUST:** Retain an existing `iptv_live` or `custom_linear` playback session when navigating between first-party app routes; the current live channel remains playing in an in-app docked mini-player. Include the mini-player in the first-release scope.
- **PLAY-14 MUST:** Keep a **single player instance and upstream live session** across expanded/docked transitions; do not remount the media element, restart the HLS loader, reauthenticate or issue an extra transcode solely because of route changes. Maintain current playback state, captions, volume and mute settings.
- **PLAY-15 MUST:** Provide accessible and keyboard-operable dock controls: Restore/Expand, Stop/Close, Mute/Volume and supported source-specific controls; preserve the `LIVE`/`Behind Live` state and custom-channel Pause/Resume/Go Live semantics. IPTV remains live-only.
- **PLAY-16 MUST:** Keep the dock non-obstructive on desktop and during dialogs; minimize must not interfere with browsing, form interaction or channel-guide filters. The mini-player remains visible across Home, Movies, TV Shows, Search and Settings routes (while an active live session exists).
- **PLAY-17 MUST:** Restore returns the viewer to the expanded Live TV player **without retuning**, moving playback backwards, losing custom-channel pause offsets or triggering Plex watch-history events.
- **PLAY-18 MUST:** Logout, revocation, explicit Stop, stale browser sessions and application teardown release live playback sessions/FFmpeg/stream refs safely. Route transitions alone must **not** execute playback cleanup.
- **PLAY-19 MUST:** Handle browser tab suspension and transient network failures without leaking streams; reconnect at the server-authoritative live position or a still-retained viewer pause position, show clear recovery states and do not promise uninterrupted playback when browser/network limitations prevent it.
- **PLAY-20 MUST (CONFIRMED):** Pressing **Play** for any Plex on-demand movie or episode while `iptv_live` or `custom_linear` is active (expanded, docked, playing, paused or behind live) must completely stop that tab's live playback **before** beginning `plex_vod`. Release the live player controller, HLS requests, pause state, timeshift/retention reference and viewer-side upstream stream authorization; remove the mini-player. Shared server pipelines may continue solely if still referenced by other authorized viewers.
- **PLAY-21 MUST:** Use an explicit asynchronous handoff state (`stopping_live` → `starting_vod` → `vod_active` or `failed`). Prevent duplicate `Play` requests, double audio, hidden live requests and playback races. Locally stop output immediately; attempt clean server-side release, with bounded retry or stale-session reaper if server/network acknowledgement fails. Never block indefinitely waiting for cleanup.
- **PLAY-22 MUST:** **No automatic Return to Live TV** at VOD completion, Back, Stop, player close or VOD errors. Do not keep a suspended live stream or a post-VOD return-channel action. Viewers may enter the normal **Live TV** guide manually and deliberately tune to any channel, starting at its then-current live position (or a new custom-channel timeshift session beginning live).
- **PLAY-23 MUST:** Preserve normal Plex VOD playback-progress/completion reporting during this transition and keep linear watch-history isolation. Stopping paused custom TV must not mark the underlying Plex movie/episode watched, and a failed VOD start must not silently restart or resume Live TV.
- **PLAY-24 MUST:** Only the initiating viewer/tab's live session is ended. Other users watching the same virtual channel continue normally on the same authoritative station clock; shared channel transcoding should shut down only when no authorized viewer or needed retained session remains.
- **PLAY-25 SHOULD:** If a network/decoder problem prevents clean shutdown, show a concise VOD start error and provide ordinary Retry and Live TV navigation; do not initiate two streams or automatically retune.
- **PLAY-26 MUST (CONFIRMED):** A server-wide administrator setting controls the maximum number of **active CPU video transcoding jobs**, default **2**. It is separate from the viewer count, IPTV provider connection limits, direct-play sessions, remux workers, audio-only conversion and pause-buffer retention. The limit is enforced across all app-controlled eligible video encoders regardless of media source.
- **PLAY-27 MUST (CONFIRMED):** When a viewer requests a new eligible CPU video transcoding pipeline and the global job limit is fully occupied, return an immediate, explicit **Transcoding capacity reached** playback error and a manual **Retry** control. Do not queue the request or automatically retry it. A Direct Play, stream-copy/remux, audio-only conversion, or authorized join of an existing shared encoding pipeline does not consume another CPU video-encoder permit and is not rejected merely because all video-encoder slots are occupied.
- **PLAY-28 MUST:** A capacity rejection must not stop or degrade existing viewing sessions, allocate any new video encoder, consume a permit, mark content watched, or create an orphan session. Apply the same behavior to Plex VOD, M3U IPTV and custom linear channels when a new video encoder is required. Preserve global channel clock and EPG state.

### 5.2.2 Audio and subtitle selection (CONFIRMED)

- **TRACK-01 MUST:** For `plex_vod` and `custom_linear` sessions, retrieve the authenticated Plex viewer's language, subtitle display and selection preferences where available through supported Plex APIs. Match them against actual media track metadata using Plex's selected stream IDs/defaults, not guessed language strings.
- **TRACK-02 MUST:** On start, apply Plex's selected/preferred audio track and subtitle policy if a compatible choice exists. Respect user preference for subtitles off or conditional/forced subtitles where represented by Plex; do not blindly turn all subtitles on. If a preference is unavailable or cannot be expressed by the current Plex API, use the source's valid selected/default track and disclose the fallback as appropriate.
- **TRACK-03 MUST:** Show accessible **Audio** and **Subtitles** controls in the player for Plex content. Display actual track labels (language, codec, forced/SDH when known), availability, selected state, and **Off** for subtitles. A viewer's manual choice applies to their playback session only; it must not mutate Plex account-wide language settings or another viewer's selection.
- **TRACK-04 MUST:** For `iptv_live`, discover only the tracks actually exposed by the provider/HLS manifest/transport and browser. Start with the provider's selected/default audio and subtitle state; present extra track options only when present and supported. **Do not apply Plex account language preferences to IPTV.**
- **TRACK-05 MUST (CONFIRMED):** At each `custom_linear` episode/movie boundary, enumerate the new item's actual tracks and **reapply this viewer's current viewing-session manual audio language and subtitle mode/language intent** when a compatible track exists. Do not reuse an old program's track ID as if it were valid for the next program. When a requested language or mode cannot be satisfied, temporarily fall back to the viewer's Plex preference/selected valid default for that program, without erasing the session override. Automatically try the saved intent again on later programs where supported. An explicit manual subtitle **Off** selection persists as Off across program boundaries.
- **TRACK-11 MUST (CONFIRMED):** Store audio/subtitle overrides as viewer- and `custom_linear` playback-session-scoped *intent* (language, subtitle Off/On/forced behavior, and accessible matching variant where identifiable), not persisted Plex account settings, app-global defaults, or old Plex track IDs. The browser-visible UI must distinguish the requested preference from the effective track when a fallback is active.
- **TRACK-12 MUST:** A `custom_linear` viewing session begins when an authenticated viewer selects a station and ends on Stop, changing stations, starting Plex VOD, sign-out, expiry or other definitive session close. Docking/restoring the mini-player, pausing/resuming, Go Live and switching programs **must not** create a new session or reset its track intent. Returning to the same channel after ending a session starts from Plex preferences again. Do not persist the override for later visits or server restarts after session termination.
- **TRACK-13 MUST:** Restore Plex-based language/subtitle defaults on **new custom-channel sessions**, even when the same user previously chose a different language on that channel. Ensure the first selected tracks on any new station session are resolved from the newly fetched eligible program and viewer account.
- **TRACK-14 MUST:** Keep track intent separate from the underlying shared broadcast video timeline, pause cursor, buffer retention and Plex watch-history state. Reapplying or falling back on track intent may never jump the viewer back to live, skip a program, alter another viewer's selection, scrobble to Plex, or trigger a prohibited 4K HEVC video encode.
- **TRACK-15 MUST:** Apply server-side authorization, track-availability validation and standard transcoding resource admission at every requested track switch/automatic program transition; reject unsupported variants and show the actual selected/fallback state. Never silently start a new eligible encoder when the global limit is exhausted, and never enter a transcoding queue. A no-compatible-subtitle case may disable subtitles while leaving playable video intact.
- **TRACK-16 SHOULD:** Preserve semantic track distinctions when known (e.g., commentary, descriptive audio, forced/SDH subtitles). A language match must not automatically select a commentary track over a normal-language track unless the viewer chose that variant.
- **TRACK-06 MUST:** Prefer browser-rendered selectable text subtitles, supported subtitle extraction/conversion and video-copy paths when permitted. A request for subtitles on a **4K HEVC** video must never trigger subtitle burn-in, scaling, HDR tone mapping or another video encode. If the track cannot be displayed without prohibited encoding, show **Subtitle unavailable for this playback** without changing the video route.
- **TRACK-07 MUST:** Permit audio-only remux/conversion on a compatible video-copy path when required and permitted by host policy; do not charge such work against the global **CPU video transcoding** job count. Enforce separate CPU resource safeguards and backend token/access checks. If an eligible 1080p-or-lower video encode is needed for a legal subtitle/track route, it must obtain an available encoder permit or fail immediately with the confirmed capacity error and manual Retry.
- **TRACK-08 MUST:** Keep track choices per viewer even when viewers share a channel's underlying schedule. Share an encoded pipeline only when the chosen output and access model are compatible; do not accidentally force viewer A's audio/subtitle language onto viewer B or duplicate encoders without reserving a permit.
- **TRACK-09 MUST:** Preserve VOD resume offset or valid custom-channel pause position during a successful manual track switch. If a track switch fails, continue the prior working rendition when possible and show a clear error. IPTV channel-track changes remain live-edge only, without timeshift.
- **TRACK-10 MUST:** Do not expose full Plex/playlist credentials or raw privileged subtitle endpoints to browser clients. Enforce item-level access on audio/subtitle metadata and delivery, and apply safe language/track-ID validation and subtitle sanitization.

**Operational note:** Plex preference retrieval is a priority for Plex media, but a custom client must still verify what the current Plex APIs actually expose for each signed-in account. Respecting Plex preferences does not justify silently writing user preferences back to Plex. This spec establishes product behavior, not an unverified promise about a particular SDK method.

### 5.3 IPTV sources

- **IPTV-01 MUST:** Add one or more **M3U live-TV** playlists by administrator-supplied URL or uploaded playlist file. Support HTTPS URLs and provider-specific request headers where approved/needed.
- **IPTV-02 MUST:** Parse M3U entries and import **live channels only**: source ID, `tvg-id`, name, stream URL, logo and group/category when supplied. Ignore any non-live/VOD entries.
- **IPTV-03 MUST (CONFIRMED):** Ingest the provider's **XMLTV/EPG** feed by URL or upload. This is a primary supported workflow, not a later optional integration. Permit live playback if the feed is temporarily missing or incomplete.
- **IPTV-04 MUST (CONFIRMED):** Independently refresh M3U playlists and XMLTV feeds at **administrator-configurable, per-source intervals**, with confirmed initial defaults of **12 hours for each M3U source** and **6 hours for each XMLTV feed**. Offer a protected **Refresh Now** action for each source/feed. Preserve last good XMLTV guide data, channel mappings and admin overrides through failures. Every successful, validated M3U refresh must apply the confirmed new-channel approval/missing/restore rules; a failed or partial fetch must never be interpreted as deletion.
- **IPTV-05 MUST:** Support administrator channel enable/disable, rename override, logo override, group, **global display number and lineup position**, favorite eligibility and visibility. Persist overrides across M3U and XMLTV refreshes.
- **IPTV-06 MUST:** Play IPTV directly in the app without Plex DVR/tuner configuration; prefer HLS/direct pass-through, use stream-copy/remux if allowed and necessary, and respect the **CPU-only and no-4K-HEVC-video-transcode** rules for every IPTV source.
- **IPTV-07 MUST:** Handle HLS, and supported MPEG-TS after remux as needed; detect unsupported or provider-specific transport with helpful errors. When the source provides multiple audio or subtitle tracks, expose its supported choices without applying Plex-account language preferences; use the provider default if no viewer override is selected.
- **IPTV-08 MUST (CONFIRMED):** When the upstream IPTV provider **permits server-side stream relaying/sharing**, multiple authorized viewers tuned to the same external M3U channel should reuse **one active upstream provider stream** if their requested renditions, audio/subtitle tracks, credential scope and stream protocols are compatible. Do not multiply provider connections just because another authorized viewer opens the same station. The operator is responsible for ensuring the subscription/license permits this use; sharing does not override a provider's connection, household, geography or redistribution rules.
- **IPTV-15 MUST:** Centralize an upstream stream registry keyed by stable provider/source ID, channel identity, credential/authorization scope, effective upstream rendition and other relevant compatibility dimensions. Use atomic single-flight startup plus reference counting or leases to prevent simultaneous tune-ins opening duplicate provider sessions. Track separately: **upstream provider connections**, **downstream viewer sessions**, and **app-managed video encoder jobs**.
- **IPTV-16 MUST:** Each viewer retains an independently authorized opaque app session and manifest/segment access. Check sign-in and IPTV permissions on every delivery path; a cached shared stream must not bypass viewer authentication, source entitlement or revocation. Never reveal raw provider URLs, headers, cookies or credentials in client manifests, logs or public diagnostics.
- **IPTV-17 MUST:** Reuse an already-running compatible HLS/remux/transcoded output where safe. If viewers request different qualities, audio selections, transport variants or server-side encoding, only share compatible upstream and downstream stages. Never force one viewer's track choice onto another, violate the default-two configurable CPU encoder budget, or transcode prohibited 4K HEVC. If a required new upstream provider stream is not permitted or would exceed the provider's connection limit, fail with a clear **IPTV_CONNECTION_LIMIT** or **IPTV_SHARING_UNAVAILABLE** message, not an unauthorized second connection.
- **IPTV-18 MUST:** A viewer leaving, switching stations, starting Plex on-demand playback or signing out releases **that viewer's reference** without interrupting other viewers. Close the upstream only after the last eligible viewer disconnects, optionally after a small **PROPOSED 15-second idle grace** to avoid unnecessary channel-zap reconnects. Never leave orphan FFmpeg jobs, unused upstream HTTP sockets or unlimited segment caches; clean up after crashes/timeouts.
- **IPTV-19 MUST:** Treat shared IPTV as a **live-only stream**. Do not enable per-viewer pause, rewind, timeshift or recordings through a shared segment cache. Newly tuning viewers join the current live edge, not stale buffered content. Provider XMLTV scheduling, favorites, numbering and the mini-player do not alter sharing identity or the upstream timeline.
- **IPTV-20 MUST:** Support providers that require per-connection or per-account authorization, have session-bound URLs or forbid restreaming. In such cases do **not** share across incompatible credentials/accounts. Do not silently open individual upstream streams when sharing is disallowed if that would exceed the provider's authorized concurrent connections; enforce documented provider policy and report unavailable playback. Admin visibility should show sharing eligibility and limit reasons without exposing secrets.
- **IPTV-21 MUST:** Handle provider disconnects, source refreshes and application restarts without mistakenly duplicating upstream sessions. Treat M3U playlist refresh as a source metadata update rather than automatically destroying an active healthy live stream; reconcile changed URLs/credentials on the next safe connection or an explicit provider-required refresh.
- **IPTV-22 SHOULD:** Provide read-only administrator diagnostics: live viewers by channel, active shared provider connections, stream startup failures, source limit state and whether an HLS/remux/video transcode pipeline is shared. Redact identifying provider tokens and viewer-sensitive request details.
- **IPTV-23 MUST (CONFIRMED):** Automatically attempt to restore an **unexpectedly interrupted IPTV source stream** that had an active viewer, including upstream disconnects, connection resets, stalled HLS playlists/segments, and defined read timeouts. Automatic recovery is **finite**: after a bounded number of attempts, the app enters a terminal recoverable error state and displays **Retry**. Do not retry indefinitely.
- **IPTV-24 MUST:** Use a configurable internal recovery policy with **PROPOSED defaults** of 3 reconnection attempts, increasing delays of approximately 2, 5, and 10 seconds, bounded per-attempt connection/read timeouts, and limited jitter to prevent simultaneous provider hits. Exact counts, jitter and timeout values are engineering defaults to validate; do not confuse this proposal with user-confirmed values. Reset attempt counters only after a successful, stable reconnect, not after an immediate failure loop.
- **IPTV-25 MUST:** Present an accurate **Reconnecting (attempt N of max)** or equivalent status in the full player and docked mini-player, retain the selected channel and authorization context, and keep stop/change-channel actions responsive. When exhausted, show a clear **Stream interrupted — could not reconnect** error with a **manual Retry** action. Manual Retry starts a fresh capability/authorization check and one new bounded recovery cycle; it is never an unbounded loop.
- **IPTV-26 MUST:** For a **shared IPTV upstream**, use a **single coordinated recovery controller** per affected upstream pipeline. All attached viewers see the appropriate reconnect state, but a connection loss must not trigger an upstream retry per viewer. An authorized viewer joining while the upstream is recovering attaches to the existing recovery effort, not a redundant provider connection. On successful reconnection, reattach healthy downstream sessions to the live edge without introducing duplicate encoders, double audio, or an unauthorized extra upstream connection.
- **IPTV-27 MUST:** Explicitly cancel recovery attempts when the final viewer leaves and the idle grace expires, the viewer signs out, channel/source is disabled, playback switches to Plex VOD, the app shuts down, or authorization is revoked. A viewer changing channels must not retain an invisible reconnection worker for the old station. On an app restart, do not automatically resume streams with no active authenticated viewers.
- **IPTV-28 MUST:** Separate **transient provider/network failures** from permanent or policy errors. Never automatically retry `TRANSCODE_CAPACITY_REACHED`, `QUALITY_NOT_PERMITTED`, unsupported/prohibited 4K HEVC conversion, invalid authorization, forbidden provider sharing, or provider concurrent-connection-limit refusals. The confirmed no-queue/manual-Retry-only CPU-capacity rule has priority over this IPTV network recovery policy. Stop or defer retry on provider HTTP `429` / `Retry-After` and other provider rate-limit signals; never hammer an upstream source.
- **IPTV-29 MUST:** Retry only through approved provider endpoints using protected backend credentials; honor the M3U provider's concurrency and rate policies on every attempt. If playlist data or credentials have changed during a failure, refresh only as authorized and without destroying other healthy streams. Avoid retrying stale expiring URLs indefinitely.

### 5.4 Custom 24/7 channels

- **LINEAR-01 MUST:** Let admins create, rename, order, disable and delete custom channels with channel number, title, logo and summary.
- **LINEAR-02 MUST (CONFIRMED):** Admin creates and edits **application-owned custom channel playlists only inside this web app**, selecting Plex movies, individual episodes, seasons, or whole series from an integrated Plex library browser. Whole series/seasons expand in normal **season number then episode number** order. **Importing or editing existing Plex playlists is excluded** from the product requirements unless separately requested later.
- **LINEAR-03 MUST (CONFIRMED):** Maintain a **continuously advancing shared wall-clock broadcast schedule**, independent of viewers and process uptime. At a given time, new live viewers see the same on-air program and approximate position; independently paused viewers intentionally remain behind live.
- **LINEAR-04 MUST (CONFIRMED):** On tune-in, locate the program from the authoritative server clock, compute `playbackOffsetMs = scheduledEntry.mediaOffsetMs + (serverNowUtc - scheduledEntry.startUtc)` and seek to the correct in-item position. Account for stream startup lag so the viewer is not systematically behind the scheduled broadcast.
- **LINEAR-05 MUST:** Generate a persisted deterministic timeline from the ordered playlist, exact available file durations and an anchor start time. Extend to a rolling guide horizon (**PROPOSED:** seven days). The timeline loops from the last item to the first, with no per-viewer schedule changes.
- **LINEAR-06 MUST:** Show custom channels alongside provider IPTV channels in the same EPG grid, with channel logos and now/next items. The custom schedule is identical for every authorized viewer, since all intended users share Movies and TV libraries.
- **LINEAR-07 MUST:** Skip, replace or clearly mark unavailable Plex items without collapsing the entire channel.
- **LINEAR-08 MUST:** Advance schedules **as database/time calculations, not as constantly playing video**. Keep channels without active or valid paused sessions idle; start FFmpeg only on demand. An active paused viewer may require continued segment generation/retention until the pause window or session expires.
- **LINEAR-09 MUST:** Handle item boundaries without breaking the player's stream; use common output profiles / segment discontinuities and test mixed codecs, aspect ratios and audio tracks. At each boundary, enumerate the successor item's track options and apply that viewer's Plex preference-compatible selection without leaking another viewer's manual track choice; manual override carryover remains an explicit open decision.
- **LINEAR-10 MUST (CONFIRMED):** Support manual reorder, natural episode ordering, start anchor, continuous repetition/looping, preview of forthcoming airings and safe publishing of edited playlists. At the safe publish cutover, advance to the current program occurrence's successor in the **new** list, or start from its first entry if removed. Random shuffle, weighted rotation, themed/time-of-day blocks and advanced rerun rules are **LATER**.
- **LINEAR-11 LATER:** Channel bumpers, commercials, interstitials and filler clips with time accounting are not MVP requirements.
- **LINEAR-12 MUST (CONFIRMED):** Administrator-published programming edits **activate at the end of the currently airing episode/movie**, never midway through it. Recompute future guide entries from that handoff boundary without rewinding viewers or corrupting historical entries needed by delayed sessions.
- **LINEAR-13 LATER:** Export of authenticated M3U/XMLTV endpoints for external players is a separate product decision; **not needed** to run channels in this web app.
- **LINEAR-14 MUST (CONFIRMED):** The first release has **one globally synchronized station schedule per channel**, never a per-viewer station schedule. Viewers **may pause their own playback** while the shared station clock continues. No schedule reset when the first viewer tunes in.
- **LINEAR-15 MUST (CONFIRMED):** Custom linear-channel playback is **strictly separate from Plex VOD watch history and Continue Watching**. No scheduled media item can change the viewer's Plex watched flag, progress, resume offset, play count or last-viewed timestamp. All viewer-local pause/resume state is app-owned and unrelated to Plex media-title progress.
- **LINEAR-16 MUST (CONFIRMED):** Only on custom Plex-powered channels, provide **Pause**, **Resume** and **Go Live**. Pausing freezes an individual viewer's playback position, never the station's scheduled position or another viewer's playback.
- **LINEAR-17 MUST (CONFIRMED):** Resume from the *same viewer's paused media timeline*, including through a scheduled program boundary when retained segments exist. The viewer remains behind live until selecting **Go Live**; resuming does not automatically catch up.
- **LINEAR-18 MUST (CONFIRMED):** **Go Live** leaves the viewer's delayed playback, resolves the latest authorized on-air program from the server clock, and starts near its current live position. The viewer does not need to stop/reopen the channel.
- **LINEAR-19 MUST:** Provide a backend-managed, **bounded rolling HLS segment buffer** (or equally robust equivalent) to keep paused content available. Do not assume `HTMLVideoElement.pause()` alone preserves expired upstream segments. Segments must be indexed against channel schedule time and retained across file/episode boundaries within policy limits.
- **LINEAR-20 MUST:** Keep each viewer's pause/resume offset and session state independent, even if channel video segments are shared. The MVP assumes all intended viewers can access all Movies/TV source libraries and therefore presents one shared channel timeline without viewer-specific replacement content. **Enforce authorization separately for every viewer** before manifests, buffered segments and program transitions, so later permission changes cannot leak restricted media.
- **LINEAR-21 MUST:** Identify buffer exhaustion (pause longer than retention, inactivity timeout, disk limits), session expiry, channel changes, or server reboot. Never silently restart the wrong show. Show a clear **buffer expired** message with a **Go Live** recovery action; choose automatic live fallback only after an explicit UX decision.
- **LINEAR-22 MUST (CONFIRMED):** Pause retention for custom channels is **server-wide and administrator-configurable** at **Settings → Channels → Playback & Buffering**, with a persisted **30-minute default**. The value caps how far behind the live broadcast a viewer may remain, including while resumed and playing delayed; it is not merely how long the Pause button may remain engaged. Bound disk use by this duration **and** separate safety quotas/concurrency limits. Release unused segments when no valid session needs them.
- **LINEAR-23 MUST:** External M3U IPTV remains strictly live in MVP: no viewer-local pause, rewind, restart, recording, or IPTV segment retention implied by custom channel controls. Adapters/controls must be source-aware.
- **LINEAR-24 MUST:** When a user changes channels, ends playback or signs out, terminate their paused session and free only the buffer resources no longer needed by other viewers. Resume on returning to that channel starts live unless a separate restore-session decision is made.
- **LINEAR-25 MUST (CONFIRMED):** Only a Plex-authenticated application administrator can view or update the server-wide retention value. Save it durably in application settings, validate updates server-side, and apply it consistently to every custom channel and viewer session. A newly installed server must default to 30 minutes without setup.
- **LINEAR-26 MUST:** Expose current configured limit, measured available buffered duration, per-channel cache usage, total cache usage, active paused/delayed sessions, and storage-pressure/error state in admin diagnostics. Never promise retention beyond what available storage can satisfy.

Show a confirmation/warning in the settings UI before applying a reduction. Increasing retention only expands the maximum for content buffered *after* the change, not video already discarded.
- **LINEAR-28 MUST:** Pause retention is an upper bound, not a storage guarantee: separate disk/cache capacity, permission changes, source failures, and server restarts can shorten the available window. Enforce hard disk limits and storage-pressure cleanup regardless of the administrator's duration selection; affected users see **Buffer expired · Go Live**.
- **LINEAR-29 MUST (CONFIRMED):** All custom channel playlists, playlist entries, ordering, channel metadata, and schedule drafts are created, stored, and edited **within this application**. Plex remains the read-only source for media selection, metadata, artwork and authorized playback; do not depend on Plex playlist APIs for channel composition.
- **LINEAR-30 MUST:** Provide an in-app **Plex media picker** that can search/filter the shared Movies and TV Shows libraries and drill into shows, seasons and episodes. Admins can add one or more movies, a whole series, a whole season, or selected individual episodes, and can see selected-count feedback.
- **LINEAR-31 MUST:** When adding a show or season, expand its currently available playable episodes into clearly visible entries ordered by season number and episode number. Exclude duplicate imports caused by repeated selection unless the admin intentionally adds a repeat. Handle specials and missing/unplayable files explicitly. When a whole TV show is selected, expose its per-show automatic new-episode setting; a season-only selection can also use the setting but must remain limited to that explicitly selected season. Individual episodes and movies never gain an implicit auto-update setting.
- **LINEAR-32 MUST:** Support adding, deleting and manually reordering program entries, including mixing Movies and TV episodes in one list. Show entry title, season/episode label where relevant, runtime, artwork thumbnail, total list runtime and a schedule preview. Provide keyboard-accessible reorder controls in addition to drag-and-drop.
- **LINEAR-33 MUST:** Save drafts independently of published schedules. Only an administrator can publish a new immutable playlist version; editing a draft cannot alter an already-airing slot or a viewer's paused buffer. Validate that a channel has at least one playable entry before publication.
- **LINEAR-34 MUST:** Store stable Plex media references, display metadata and the resolved episode order as **app-owned playlist data**, revalidating media on sync/playback. Do not write or modify the user's original Plex libraries, collections or playlists. Rebuild or warn on a removed/inaccessible media item without losing the editor's list/order.
- **LINEAR-35 MUST:** No Plex playlist import/export UI, Plex playlist selection, or Plex playlist synchronization in the MVP. This limitation concerns **Plex playlist objects**, not the M3U playlist used for IPTV imports.
- **LINEAR-36 MUST (CONFIRMED):** In **Channel Manager**, each selected TV show exposes an independent **Automatically add new episodes** toggle. Its value is stored *per show selection, per channel*, not as a global Plex or application setting. Enabling it for one show never updates another show or the same show on a different channel.
- **LINEAR-37 MUST:** Enabled selections are checked against Plex during catalog refresh and at a scheduled background interval. Identify genuinely new playable episodes using stable Plex server and episode IDs, not title text or metadata-change timestamps. A repeat sync must not add duplicate programs; manual repeat entries stay possible only through an explicit admin action.
- **LINEAR-38 MUST:** New episodes join the app-owned playlist in **natural season and episode order within their originating show/season group**, without discarding unrelated movies, custom ordering or explicitly created repeats. Respect a stored exclusion/removal record so an admin-deleted episode is not silently re-added by the next sync; the admin can re-include it manually. Specials and unnumbered items follow the existing explicit selection rules.
- **LINEAR-39 MUST:** Schedule updates from auto-add use an atomic published revision effective at a **safe future item boundary**. Never interrupt a currently airing movie or episode or alter the retrospective schedule still needed for viewer-local Pause/Resume buffers. Recompute future EPG entries and keep already-started/current stream segments mapped to their original version. No manual republish is required when the toggle is enabled.
- **LINEAR-40 MUST:** Display each show's auto-add state, last checked time, last result, pending additions and errors in the channel editor. Provide an admin **Check for new episodes** action and an audit trail indicating which program items came from an automatic refresh. Disabling auto-add stops future imports but does not remove items already added.
- **LINEAR-41 MUST:** A Plex sync failure must preserve the last known good program list and schedule; queue or retry after recovery. Newly discovered episodes are not inserted when missing duration/stream eligibility or conflicting identifiers would corrupt scheduling. Flag them for admin review and maintain uninterrupted existing programming.
- **LINEAR-42 PROPOSED DEFAULT:** Initialize each new show selection with auto-add **off** until the admin enables it; make that default visible in the editor. This default is a recommended UX choice, not yet confirmed by the user.
- **LINEAR-43 MUST (CONFIRMED):** When an administrator publishes a change to an **already-active** custom channel, retain the entire currently airing `ScheduleEntry` through its original `endUtc`. The new playlist revision becomes active at **the next episode/movie boundary** (the current entry's end time), with no immediate cut, seek, restart or time shift for live viewers. This applies when media items are added, removed or reordered, including removing the item presently airing.
- **LINEAR-44 MUST:** Persist a **pending publication** with its immutable playlist revision, the previously active revision, `effectiveAtUtc` (the current entry's existing `endUtc`), publishing admin and submission time. Publishing acknowledges the saved revision and displays a **Pending · Goes live at [local time]** state until the handoff. A newly created/never-published channel may establish its initial anchor and start according to the normal initial publication flow; it has no on-air item to protect.
- **LINEAR-45 MUST:** At cutover, preserve all real-time timestamps: the old current entry ends at its original UTC boundary and the **selected successor or fallback first entry** of the new revision begins **at that exact UTC instant**. No empty slot, overlapping slots, retroactive schedule shift or second channel clock is permitted. Persist the active/pending state transactionally so a process restart before or at cutover resolves the same revision, first new entry and live offset as if it had never restarted.
- **LINEAR-46 MUST:** The guide must continue to show the **correct current on-air program** after Publish and regenerate **future EPG entries from the pending boundary** using the new version **starting with the selected next entry** (not necessarily entry one). Show the next program and pending-effective-time indicator in Channel Manager; viewers may see the new upcoming programs in the guide, but never a different title for the program already airing. Keep previous schedule history until the configured delayed-playback retention and active leases no longer require it.
- **LINEAR-47 MUST:** Paused/behind-live viewers retain their own timeline and the old schedule's media/segments across the handoff (within effective buffer retention). When their playback reaches the boundary, they transition to the new program sequence at their delayed position. **Go Live** always jumps to the current active schedule revision and clock position, not the previous playlist version. The update may not silently expire an otherwise valid viewer buffer.
- **LINEAR-48 MUST:** Publishing a second edit before the first takes effect must not create competing cutovers or compound schedule jumps. Use one pending publication per channel: the most recent explicitly confirmed valid publish **replaces** the prior pending revision for the same scheduled handoff; preserve an audit trail and show the supersession in admin UI. Guard against stale concurrent edits using playlist version/revision preconditions.
- **LINEAR-49 MUST:** Schedule publication and transition events must be atomic and idempotent. Recover correctly if Publish happens milliseconds before a boundary, if two admins publish concurrently, or if the scheduler job runs twice. Calculate the effective boundary based on one transactionally consistent authoritative `nowUtc` and current slot; never schedule activation in the past.
- **LINEAR-50 MUST:** Apply the same safe-boundary guarantees to the per-show **automatic new episode** update process. Auto-sync must not supersede an administrator's pending publish without a conflict-safe merge or an explicit review; never silently discard curated edits.
- **LINEAR-51 MUST:** Validate edited playlists and playable durations before publishing; reject invalid/empty lists without disturbing the active schedule. Distinguish planned edits from emergency recovery when the current media is removed or becomes unplayable; use the existing deterministic fallback and surface the warning, not a hidden mid-program edit cutover.
- **LINEAR-52 MUST (CONFIRMED):** At the next current-program boundary, activate the revised ordered playlist and **start with the entry immediately following the just-finished program's retained occurrence in the new playlist**. Wrap from the new playlist's last entry to its first. If that on-air program occurrence was removed from the revised playlist, **start with the revised playlist's first entry**. The currently airing program must always finish at its original end time, including when deleted from the revision.
- **LINEAR-53 MUST:** Match the program occurrence using its **stable application-owned playlist-entry ID**, not merely its Plex ratingKey/title or list index. Preserve an entry's ID when an administrator reorders it or inserts entries around it. Each intentional duplicate of the same Plex title gets its **own** entry ID. Deleting and re-adding an occurrence creates a new ID and is treated as removing the original (fallback to item one).
- **LINEAR-54 MUST:** Determine the successor from the **fully validated, published new order**, not from the previous playlist's next position or a stale EPG projection. Example: Old `[A, B(on air), C]`, new `[A, B, X, C]` means `X` follows `B`. New `[C, A, B]` means `C` follows `B` because the list loops. New `[A, X, C]` means `A` follows `B` because `B` was removed.
- **LINEAR-55 MUST:** Persist a pending publication's resolved `cutoverAfterEntryId`, `nextEntryId` and effective UTC boundary in the same transaction as the immutable revision. Recompute the candidate successor when replacing an unpublished pending revision. Reject inconsistent drafts before publishing; do not guess if stored identity/version is corrupt.
- **LINEAR-56 MUST:** At exactly `effectiveAtUtc`, schedule the resolved successor as the first new entry with offset zero, followed by all remaining entries in published order (wrapping normally). Do **not** reset the current program or anchor the entire new loop at its first entry unless the old program occurrence was removed. Regenerate future EPG from this exact handoff.
- **LINEAR-57 MUST:** A viewer paused on the prior timeline can finish buffered content before crossing the new cutover; a viewer joining live after the boundary sees the chosen successor at the correct clock offset. Subsequent publishes repeat the same rule against the program actually airing at their own safe boundary. Existing viewer session cursors and segment references remain stable within retention policy.
- **LINEAR-58 MUST:** Surface the resolved handoff in the admin's publication preview: **Current [title] finishes at [time] → Next [title]** and explicitly indicate when a missing current entry causes **restart at the first entry**. This preview must agree with guide data and the persisted publication record.
- **LINEAR-59 MUST (CONFIRMED):** Never issue Plex scrobble/unscrobble, title-playback timeline/progress or watched-state write operations from a custom linear session, including at the end of an episode or while a program plays unattended. The backend enforces this regardless of incoming client behavior.
- **LINEAR-60 MUST:** App-local last-tuned channel, favorite, active station session and paused cursor are permitted; they must never contribute to Plex on-demand title history or Continue Watching.
- **LINEAR-61 MUST:** A user's simultaneous or later Plex VOD session must report progress normally and must not be overwritten by a custom-channel session for the same underlying media item. User separation and session isolation are required.



### 5.5 Unified TV experience (CONFIRMED guide and lineup)

- **TV-01 MUST:** Every channel has an immutable internal channel ID distinct from its editable public channel number, external M3U/XMLTV IDs, and sortable lineup position. Use one namespace for **display channel numbers across all sources**.
- **TV-02 MUST:** Show imported IPTV and app-generated custom TV channels in **one EPG and one player**, using the same time ruler and a common globally defined lineup. By default, All Channels includes every enabled, viewer-accessible channel.
- **TV-03 MUST:** The desktop guide has four primary selectable filters with these exact labels: **All Channels**, **IPTV**, **Custom Channels**, **Favorites**. **IPTV** includes only external M3U live channels; **Custom Channels** includes only scheduled Plex-content stations. **Favorites** includes both types, limited to channels favorited by the signed-in user.
- **TV-04 MUST:** Favorite/unfavorite operations are **per Plex-authenticated viewer**, not global lineup edits. A favorite must be accessible through its original channel number and preserve its relative administrator-defined lineup order. Favorites only changes discovery and preference, not authorization or the station schedule.
- **TV-05 MUST:** Provide an **administrator-only** channel lineup manager for all source types. Admins may assign/change display numbers, adjust global order by drag-and-drop or keyboard move controls, and enable/disable channels. Ordinary viewers may not change global order or numbering.
- **TV-06 MUST:** Enforce **unique display numbers among active IPTV and custom channels**. Show a validation error on manual collisions (do not silently replace or merge another station). On M3U import, preserve a previously mapped app number and order; for a genuinely new **auto-approved or administrator-approved** channel with an absent/colliding upstream number, assign a deterministic next available number. A **pending** discovery has no public lineup number until admission; source upstream numbers remain metadata. Never renumber an existing approved channel to fit a new entry.
- **TV-07 MUST:** Separate **channel number** from **sort position**. Renumbering does not erase favorites or break playback links, and dragging to reorder does not implicitly renumber. Active player sessions remain anchored to stable internal IDs when metadata or lineup position changes.
- **TV-08 MUST:** Guide renders historical, present, and upcoming programs with viewer timezone and DST support. Show now/next information and current program progress. Tune immediately when selecting the currently airing program; future entries only open program details.
- **TV-09 MUST (CONFIRMED cached EPG rule):** Display XMLTV data for IPTV channels only where the current valid feed snapshot or retained last-good snapshot has authentic program entries covering the queried time range. After refresh failure, keep those cached entries inside their original scheduled windows; fill all remaining gaps, including after the final known program, with the visible **No guide data** fallback. Do not extend, repeat or fabricate old listings, and do not treat guide unavailability as channel-stream unavailability. Custom channels display their independently generated schedules. Do not duplicate a channel row when multiple source identifiers happen to match the same provider schedule.
- **TV-10 MUST:** Channel and guide APIs never reveal provider tokens, raw protected stream URLs, or privileged Plex endpoints. Validate access to every channel and media stream separately from filter selection.
- **TV-11 MUST:** Preserve administrator number/order/name/logo/visibility overrides when sources refresh or XMLTV programs change. Source refreshes must not create duplicate numbered rows or unintentionally unhide disabled channels. **Unapproved Pending Review channels are invisible to every ordinary viewer-facing guide/list/filter/search/playback endpoint until admitted, independent of EPG availability.**
- **TV-12 MUST:** Filters operate consistently across the guide and sidebar/list. Switching filters must not reset the playhead, change the shared broadcast clock, or automatically stop an already playing channel; if the active channel is outside a selected filter, keep playback and indicate the selection is outside the visible list.
- **TV-13 SHOULD:** Persist each viewer's last selected filter and guide scroll position; allow quick switching, keyboard navigation and favorites from the guide, player overlay and channel detail view. Optional provider category/group filtering can be added without replacing the four primary filters.
- **TV-14 MUST:** Provide a useful empty state for a category with no channels and for a signed-in viewer with no favorites. Allow returning to All Channels; do not imply missing guide data means the underlying channel is unavailable.
- **TV-15 MUST (CONFIRMED):** Viewer guide, IPTV/All/Favorites filters, channel details/search and new-tune routes must exclude a previously approved IPTV channel as soon as a successful complete M3U refresh marks it missing. Do **not** substitute a public Unavailable row or retain the channel in Favorites merely because its favorite relation remains stored. Other channels keep their numbers and order; only admins can inspect the preserved missing record.

### 5.5.1 Unified guide/lineup edge cases and UI interactions

- **All Channels** is selected on first visit and lists active authorized IPTV and Custom Channels together. Both sources use one standard channel card/row: `{channel number, logo, name, source kind, current program, next program, favorite state}`.
- Filter state is **viewer-local**. Favoriting a channel for one account must never modify another viewer's favorites. Channel order/number is **server-global**, editable only by admins.
- Admin channel creation/import assigns a stable internal ID before any public number is chosen. **Pending Review records do not receive public numbers or appear in the guide**; once approved manually or through enabled per-playlist Auto Add, channels receive unique final display numbers without changing existing manually assigned numbers. If a candidate number collides, the admin review UI shows the conflict and a suggested free slot.
- An admin can change an IPTV or custom channel's number or relative position without regenerating a custom channel's broadcast playlist/schedule and without forcing active viewers to retune.
- Optional second-level grouping by IPTV provider category is **LATER**; it must not become an alternative separate IPTV-only EPG.
- Channel changes are applied as an atomic lineup revision. If a bulk reorder/renumber request conflicts with a more recent administrator update, reject or require a refresh instead of partially writing an inconsistent state.

### 6.2 Installation and operational design (Linux native)

```text
Internet browser
       |
       | HTTPS
       v
Owner-managed reverse proxy (public HTTPS, custom domain)
       |

       v
```

- Suggested installation: `/opt/unified-media/` (application code), `/var/lib/unified-media/` (SQLite, channel images and state), `/var/cache/unified-media/` (bounded segments, thumbnails), and `/etc/unified-media/` (configuration and protected secrets). Exact paths are configurable.
- Ubuntu/Debian prerequisites: supported Node.js LTS, npm or pnpm, `ffmpeg` and `ffprobe`, SQLite runtime/build requirements, and `systemd`. The pre-existing reverse proxy is **owner-provided infrastructure**, not an installation dependency for the application package. Provide tested app installation steps once the host release is confirmed.
- No application-managed public ports or TLS termination are required. The owner's existing proxy handles the public HTTPS port(s), forwarding the selected internal app port. Firewall the app port from the public internet; Plex's existing remote setup is independent, and no raw media-worker port may be published.
- An installation validation command should report Linux/Node/FFmpeg versions, Plex local connectivity, local listener/bind status and port collisions, configured public HTTPS base URL, XMLTV feed status, and streaming capabilities without exposing credentials. External proxy reachability checks must be informative rather than hard requirements for local startup.
- Build with a supported Node.js LTS runtime and package manager; serve compiled assets rather than requiring a development server in production.
- Provide `npm run build`, `npm run start`, `npm run test` and database migration commands, plus a `systemd` service sample, environment-file template and a **generic upstream mapping example** (public domain → internal `APP_HOST:APP_PORT`). Do not provision another reverse proxy or attempt to edit the owner's existing one.
- Run backend and streaming workers with limited OS permissions. Avoid privileged ports and filesystem access to arbitrary Plex libraries; request media through the supported authenticated Plex API.
- Use automatic service restart, graceful shutdown, job/stream cleanup, log rotation or journald, encrypted-credential key management, and offline-friendly SQLite backup/restore instructions.
- The deployment must be usable **without Docker, Kubernetes or container-only GPU features**.
- Live production media endpoints must support HLS manifests/segments, long-running stream responses, and byte-range requests without reverse-proxy buffering that breaks playback. Document proxy-agnostic upstream timeouts, streaming/buffering guidance, and WebSocket upgrade handling **only if** the implemented realtime features require WebSockets.

#### 6.2.0 Configurable listener and existing-proxy integration (CONFIRMED)

- `APP_HOST`: TCP bind host/address, default **`127.0.0.1`** (proposed safe default). Permit a specific private IP or `0.0.0.0` **only with a warning** about exposure and instructions to firewall the port. Some external proxy setups require a reachable private interface rather than loopback.
- `APP_PORT`: valid nonprivileged TCP port, **default `3000` (proposed, configurable)**. Do not hardcode 3000 in the frontend, stream URLs, Plex login redirects or client-side API calls. Reject invalid port values, and fail startup clearly if the selected port is already in use.
- `PUBLIC_BASE_URL`: optional during local-only setup; **required for remote deployment**, set to the public `https://media.example.com` origin configured by the owner. Use for Plex linking/callback URLs, safe external link generation and any absolute URLs. Do not construct public redirects from untrusted request `Host` headers.
- `TRUSTED_PROXY_CIDRS` (or equivalent): explicit proxy IP/CIDR allowlist where the framework trusts forwarded protocol/IP headers. Never unconditionally trust all `X-Forwarded-*` headers. Derive secure-cookie and scheme handling from the verified HTTPS public origin and trusted proxy boundary.
- Serve the compiled frontend and **all authenticated API/streaming endpoints** from the same app listener, using relative browser URLs, so the reverse proxy needs a single upstream route. Support `/health` or equivalent without revealing internal secrets.
- Require remote clients to use the HTTPS custom domain. Prohibit mixed-content HTTP media URLs in browser responses; stream/segment/image proxying must remain within the same HTTPS origin where needed.
- Configuration may come from a protected `.env`/systemd EnvironmentFile or equivalent settings; changing the bind port is an administrator deployment operation requiring a service restart, **not** a browser-editable remote control.
- Setup documentation: pick an unused high port → configure host/port and public base URL → start the systemd service → point the owner's domain proxy to the reachable host:port → test sign-in, secure sessions and HLS playback over the domain. Do not prescribe port-forwarding/SSH tunnels or Caddy installation.

### 6.2.1 Frontend player ownership (CONFIRMED)

```text
<AppShell>
  <Navigation />
  <RouteOutlet>Home | Movies | Shows | Live TV | Search | Settings</RouteOutlet>
  <PersistentLivePlayer>                   # mounted once per authenticated tab
     <VideoElement + HLS controller />     # same source across route transitions
```

- Playback session state (`sessionId`, `channelId`, source kind, player mode, pause status, behind-live offset, source capabilities) is owned by the app-level player store. The page route does not own or destroy an active stream.
- `expanded`/`docked` is a presentation state. No new backend playback session, FFmpeg pipeline, manifest URL or HLS playhead reset is created by changing the presentation mode.
- A browser tab owns **one active playback session at a time**. Starting Plex VOD fully stops and releases the previous live session and mini-player before opening VOD; no simultaneous Live TV + VOD or automatic return to Live TV. This lifecycle rule is **CONFIRMED**.

### 6.3 Internal service boundaries

- **PlexAdapter:** Servers, credentials, server discovery, libraries, items, metadata, art, playback sessions, progress.
- **IPTVAdapter:** M3U live-TV imports, protected provider URLs, XMLTV schedule ingestion, matching/refresh state, channel updates and provider limitations.
- **ChannelScheduler:** Channel rules, deterministic timeline, safe versioned publication, source-availability reconciliation and EPG publication.
- **ChannelEpisodeSync:** Background Plex episode discovery for enabled channel show/season selections, deduplication, exclusion handling, diagnostics and safe atomic schedule updates.
- **PlaybackOrchestrator:** Determines source type, authorization, direct stream/remux/transcode strategy, client stream URL, cleanup and limits.
- **CatalogService:** Normalizes titles/channel data for UI and search without pretending all sources have identical metadata.
- **IdentityService:** First-party sessions for validated Plex-account identities, server ownership checks, viewer/library permissions and administrative roles. A valid Plex login does not independently authorize this application.
- **GuideService:** A unified read API over imported XMLTV and generated custom schedules, with provenance and refresh timestamps.

## 7. Streaming Decision Design

### 7.1 Plex on-demand media

1. Validate the signed-in user's Plex identity, access to the configured server and permission for the requested library item.
2. Query media streams/codecs, browser-reported capabilities and policy (quality, server load, remote bandwidth).
3. Choose authorized Plex direct play/direct stream/transcode path; proxy through the backend only when required by CORS, TLS, security, topology or compatibility.
4. Set up signed, short-lived app playback session routes and stream data. Do not place permanent upstream secrets in public source URLs.
5. For **`plex_vod` sessions only**, send per-user playback timeline/progress/completion updates; clean up upstream sessions. No such writes occur from `custom_linear` or `iptv_live`.

**Confirmed deployment context:** The server owner has Plex Pass and invited viewers already have shared access. [Plex support](https://support.plex.tv/articles/requirements-for-remote-playback-of-personal-media/) says an admin Plex Pass covers remote playback for authorized users of that Plex server. Test this end-to-end with real shared viewer accounts and the chosen custom-player API flow. Never assume that loopback/proxy traffic nullifies remote-playback requirements.

### 7.1.1 CPU-only playback and provider policy (CONFIRMED)

The owner reports a provider-plan minimum CPU PassMark of 30,000, 320 GB RAM and 40 Gbit/s networking, with **no GPU**. These are *advertised specifications*, not measured available internet bandwidth or guaranteed number of concurrent CPU encodes. The provider allows 4K streaming to compatible clients but explicitly **forbids transcoding 4K HEVC video**.

**Classification and hard constraint:**

1. Before choosing a playback route, inspect *source video codec, width/height, bit depth, profile/level, audio codec, container, available tracks and destination browser capability*. Treat a HEVC source with a 4K/UHD-sized frame (for example, 3840×2160) as **protected from video transcoding**; err on the side of prohibition if metadata is missing or ambiguous until probed.
2. **NEVER** invoke Plex transcoding, FFmpeg video encoding, scaling to 1080p/720p, burned-in subtitles, tone mapping or forced codec normalization that would re-encode a **4K HEVC video track**. Do not allow an Auto policy, player preference, channel transition or background retry to override this rule. Enforce it server-side for all three sources.
3. **4K HEVC direct-play path:** stream the original video without re-encoding **only when the browser/device, original stream/container path and remote delivery all support it**. If an authorized stream-copy/remux route is needed, first confirm that the hosting policy permits it and that the browser accepts the result. No 4K conversion fallback should be attempted.
4. When direct/allowed copy playback is impossible, **fail explicitly** with a helpful explanation (codec/browser incompatibility; 4K HEVC video transcoding is not permitted). For a custom station, an incompatible program must be flagged in the admin editor and safely skipped or replaced with an explicit slate under a separately approved fallback rule. **Do not silently run a forbidden FFmpeg encode** to make a schedule work.
5. **CONFIRMED Smart CPU fallback for eligible media:** for sources **at most 1920×1080 (including normal portrait equivalents)**, prefer direct playback and direct-stream/stream-copy remux, then use CPU video encoding only if the browser cannot handle the source and a slot is available. CPU transcode eligibility is evaluated from the **source** video frame size; scaling a 4K source down does not make that 4K source eligible. All 4K HEVC video transcodes are prohibited absolutely. For the MVP, all above-1080p video re-encoding is disabled, even for other codecs. Audio-only remux/transcode decisions remain subject to provider policy, client capabilities, CPU budgets, and protection of the original video bitstream.
6. Native client codec support varies across Chrome/Firefox/Safari/Edge and operating systems; build a media capability probe and test actual combinations. Offer clear playback feedback rather than promising every HEVC file will work in every browser.
7. Provider's 40 Gbit/s hardware networking does **not** by itself establish available internet upload throughput. Measure sustained external egress, concurrent playback, CPU load and startup latency. Reserve CPU headroom for Plex and app functionality.
8. Prefer shared, on-demand stream-copy/HLS segment pipelines for multiple viewers of the same synthetic channel and avoid redundant encodes. Independent 30-minute-default pause retention still requires bounded **disk** cache and may be limited by available space; a large RAM figure is not a free video archive.
9. **Compatibility risk:** Seamless transitions between files with differing codecs, HDR formats or audio layouts may require video re-encoding. If a 4K HEVC item cannot join the live channel without a prohibited encode, the channel editor must report its incompatibility instead of claiming flawless playback. Prove sequential 4K/1080p mixes and real pause-resume-boundary playback without violating provider policy.

**Sample allowed/blocked decisions (proposed processing defaults):**

| Source & playback conditions | Default processing decision |
| --- | --- |
| 1080p H.264 + AAC supported by browser | Direct play or stream-copy/remux, no video encode |
| 1080p incompatible video codec | Direct/remux when playable; otherwise admit **Smart CPU video transcoding** if a bounded encoder slot is available |
| 1080p compatible video + incompatible audio | Stream-copy video and transcode audio where needed/allowed rather than re-encode video |
| 1080p eligible source while CPU budget is full | First reuse a compatible existing pipeline or serve direct/remux if possible; otherwise **immediately show a capacity error with Retry**, without queuing or starting another encoder |
| Above-1080p non-HEVC source requiring video conversion | No CPU video re-encode in MVP; show a codec/quality compatibility message |
| 4K HEVC to compatible browser/device | Original video direct play (or verified permitted video stream copy); no video encoding |
| 4K HEVC to incompatible browser, or request for 1080p version | **Block conversion**; show clear incompatibility / offer another compatible client |
| 4K HEVC used inside sequential faux channel | Only if compliant direct/copy path supports seeking and transitions; otherwise flag or use explicit fallback |

### 7.1.2 Smart CPU transcoding controller (CONFIRMED)

- **TRANSCODE-01 MUST:** Playback admission is server-enforced and based on the **source** stream, not an output quality request. Resolve source codec, width/height, bit depth, audio/container and client capability before deciding. For the MVP, source video larger than Full HD is ineligible for CPU video re-encoding, and **4K HEVC video encoding is always prohibited**. When source probing is inconclusive, do not start a video encode until verified eligible.
- **TRANSCODE-02 MUST:** Use deterministic tiered selection: **(a) Direct Play**, **(b) direct stream / remux with unchanged video**, **(c) software CPU video encoding to a browser-compatible format such as H.264 plus AAC** when needed and permitted. Audio-only conversion with video stream copy must not consume a *video-encoder* slot, though it still consumes shared CPU resources and requires its own bounded worker accounting.
- **TRANSCODE-03 MUST:** Maintain one shared *global concurrent video-encoder budget* for app-managed CPU video transcodes across IPTV and custom channels and **app-initiated Plex VOD transcode sessions**. Prevent race conditions via atomic admission, record permit ownership/expiry, and release on disconnect, process failure, or session teardown. Avoid double-encoding the same pipeline or double-counting consumers of one shared encoded stream.
- **TRANSCODE-04 MUST (CONFIRMED):** Under **Settings → Playback & Transcoding → CPU Video Transcoding**, administrators can view and edit **Maximum Simultaneous CPU Video Transcodes**. Default is the confirmed value **2**. Persist it in the application database (not just an environment variable), load it after restarts and apply it to new admissions without restarting the server. Viewer accounts can neither read privileged operational settings nor modify them. The numeric setting must be validated as an integer within a bounded, documented safe range (**PROPOSED** 1–16, subject to benchmarking), with transactional updates, meaningful validation errors and an audit record. Do not treat the user-supplied PassMark as an assurance that two encodes will always run smoothly.
- **TRANSCODE-10 MUST:** One active *video-encoding pipeline* uses one permit, whether a single viewer or several viewers share its segments. App-initiated Plex VOD transcodes and FFmpeg encoders for custom channels/IPTV share this **app-controlled global limit**. Direct Play, video stream-copy/remux and audio-only conversion consume no video-encode permit; they remain bounded by separate CPU/network/provider resource protections.
- **TRANSCODE-11 MUST:** Check the limit using an atomic reservation **before** starting an encoder, account for pending startups and release reservations reliably after start failure, termination, disconnect, orphan cleanup or crash recovery. Enforce the setting at the backend rather than trusting frontend state. Prevent concurrent requests from oversubscribing the configured cap.
- **TRANSCODE-12 MUST:** On an admin limit *increase*, permit additional new video-encoding jobs immediately. On a *decrease*, do not abruptly kill active playback; instead deny or defer **new** reservations until active encoders drop below the new cap, then enforce the updated maximum. Display current active/reserved count and configured limit. If any active workload requires intervention due to CPU/disk pressure, the independent resource-safety policy may stop jobs safely.
- **TRANSCODE-13 MUST:** Clearly scope the promise: this setting governs video transcoding **started and managed by our application**. Plex jobs started independently by other Plex clients may also use host CPU but are not automatically controlled by this application's permit system. Monitor overall host CPU load and fail safely when external load makes another encode unsuitable; do not claim a hard cap on all host Plex transcodes without reliable monitoring/control.
- **TRANSCODE-14 MUST:** Record administrative setting changes and surface running/reserved/available video-encoder slots and observed CPU load in Settings. Never surface streaming tokens or customer M3U URLs in those metrics. When the budget is fully occupied, recheck direct/remux eligibility but never bypass the cap by spawning an untracked encode. The confirmed full-budget behavior is **immediate capacity error and viewer-initiated Retry, without queuing or automatic retry**.
- **TRANSCODE-05 MUST:** Avoid involuntary quality degradation on otherwise compatible media. If capacity is unavailable, preserve any existing direct/copy route and provide a clear capacity status rather than silently spawning another encoder. If a genuinely new CPU video encoder is necessary and the cap is full, **immediately reject that request with a clear capacity error and manual Retry**. Never enqueue a transcoding request or silently downgrade by initiating a disallowed encode.
- **TRANSCODE-06 MUST:** Match responsibility to upstream capability: prefer Plex's authenticated, user-scoped playback/transcoder flow for Plex VOD where suitable; use the application's FFmpeg workers for eligible IPTV or synthetic linear paths as needed. Never chain an unnecessary Plex video transcode into another FFmpeg video transcode. Any app-initiated Plex transcode counted toward the same admission budget must have lifecycle hooks for cleanup.
- **TRANSCODE-07 MUST:** Prioritize real-time live-channel stability and prevent new sessions from starving already playing streams. An unwatched virtual station consumes no encode slot. Segment fan-out may share one encoder among viewers of the same compatible broadcast, but paused sessions still need separate playhead/manifest management.
- **TRANSCODE-08 MUST:** Provide diagnostic counters and structured logs for route choice, rejection reason, active CPU video encodes, measured load, encoder start/stop, segment errors and prohibited 4K HEVC requests without exposing Plex/M3U credentials. Never assume `40 Gbit/s` NIC specifications represent usable remote throughput.
- **TRANSCODE-09 MUST:** User-requested output resolution or subtitles must never trigger video re-encoding of disallowed source video. Explicitly reject 4K HEVC HDR tone mapping, subtitle burn-in and scaling routes that would violate host rules. Browser-compatible 4K direct streams are still allowed without an encoder slot.
- **TRANSCODE-15 MUST (CONFIRMED):** Use **fail-fast, no-queue** admission: after validating codec/source policy and checking whether Direct Play, stream-copy/remux, or reuse of an existing compatible encoder pipeline can satisfy the request, reserve a permit atomically. If unavailable, return a capacity error **immediately** rather than waiting for a permit, storing a queued job or starting FFmpeg/Plex video transcoding speculatively.
- **TRANSCODE-16 MUST:** Use a stable machine-readable failure such as HTTP `503` with `{ "code": "TRANSCODE_CAPACITY_REACHED", "message": "Transcoding capacity reached. Please try again.", "retryable": true }` before streaming begins. The UI must show **Retry** and retain relevant media/channel context. A Retry click initiates a **new** server-side capability and capacity check; it does not reserve a future place in line, bypass limits, or automatically repeat in the background. Do not expose internal errors or media credentials. If an error occurs after playback has begun, use the player’s streaming error reporting and release resources appropriately.
- **TRANSCODE-17 MUST:** A rejected new encode request never increments the active/reserved encoder count, affects already admitted viewers, interrupts a shared channel stream, changes the authoritative custom-channel clock, or mutates watched state. Keep per-source rules (e.g., IPTV provider stream count) separate; distinguish capacity exhaustion from codec incompatibility, authorization failure, upstream failure or disallowed 4K HEVC transcoding.
- **TRANSCODE-18 MUST:** No hidden queues or automatic capacity retries in HTTP middleware, playback controllers, FFmpeg workers, Plex adapter, job scheduler, live mini-player or error recovery logic. A viewer’s deliberate click on **Retry** is the only reattempt of an explicitly capacity-rejected request. Session teardown, permit release and admin limit changes must not automatically resume that failed request. Prevent thundering herds from repeated user clicks with request idempotency/debounce, without changing fail-fast semantics.

### 7.1.3 Quality negotiation and fail-safe changes (CONFIRMED)

1. **Capability check:** Probe the source's true resolution, codec, bit depth, playable audio/subtitles, packaging and (for IPTV) available adaptive HLS variants. Combine with browser support and the viewer's requested mode. The backend, not the frontend, decides which routes are permitted.
2. **Auto policy:** Prefer a directly playable, authorized rendition; next consider remux/video stream copy, including permissible audio-only conversion; only then use an eligible ≤1080p CPU video encoder if needed to make playback possible. Do not automatically choose a new video encode when a compatible Direct Play option works merely because a lower quality *could* exist.
3. **Original policy:** Use source-native video with no video re-encode; permit remux or audio-only adaptation when needed and legal. If the viewer asks for Original on a browser that cannot decode source video, return a clear Original-unavailable message rather than treating the request as permission to change video codecs.
4. **1080p / 720p manual policy:** Prefer an existing compatible rendition under the selected resolution ceiling; if no such rendition exists, a newly encoded rendition may be generated **only when the source is ≤1080p, the chosen output is smaller than the source, source/protocol permissions allow it, and an app-controlled encoder slot is available**. Avoid artificial upscaling. A high-resolution >1080p source without a suitable pre-existing lower rendition is not eligible for software downscaling in MVP. This includes 4K HEVC, which may never undergo video re-encoding.
5. **Switch transaction:** Revalidate the session and source permissions; reserve any required capacity; prepare a viable rendition; then switch player URLs/variant tracks as appropriate. Maintain VOD position or the custom viewer's real delayed offset if still retained. Live IPTV resumes at the live edge. Failures leave the old viable route operating where feasible, and release unused reservations immediately.
6. **Error priority:** A forbidden 4K HEVC or above-1080p transcode produces **QUALITY_NOT_PERMITTED** / **SOURCE_INCOMPATIBLE**, not a false CPU capacity error. An unavailable upstream quality profile produces **QUALITY_UNAVAILABLE**; a valid new encode without an available permit produces **TRANSCODE_CAPACITY_REACHED** with manual Retry; other provider/network failures remain separate. Record supported/selected route, but never leak stream credentials.
7. **Channel item changes:** Re-negotiate the selected ceiling against each new scheduled item without interrupting the global timeline or silently violating transcoding limits. If the requested manual tier becomes unsupported, choose a compatible already-available lower/Original route only where safe and transparent; otherwise show the explicit limitation and keep the shared broadcast clock running. Viewer pause retention and Plex watched-history isolation are unaffected.

### 7.2 IPTV live streams (CONFIRMED upstream sharing when permitted)

1. Validate app login, source visibility, concurrency permissions and channel eligibility.
2. Resolve the protected M3U channel stream URL server-side; never publish upstream credentials to regular users. Determine whether the provider permits relaying/sharing and whether an already-active upstream stream matches this channel, account/credential scope and requested output. If so, atomically attach a new viewer lease rather than opening a second upstream connection.
3. Try suitable HLS pass-through when browser-compatible and secure; share a compatible active provider upstream only when the provider authorizes that relay and viewer/credential scopes match.
4. Use controlled proxy/direct-stream/remux when transport or CORS rules require it; allow **Smart CPU video transcoding only for eligible source video at 1080p or lower**, and only when codec incompatibility genuinely requires it and global concurrency admission succeeds. Block 4K HEVC video re-encoding and any above-1080p CPU video re-encoding in MVP; return a helpful compatibility error for prohibited/unsupported media, or an **immediate capacity error with manual Retry and no queue** if a new eligible encoder is required but no permit is available. A shared upstream provider stream does not mean unlimited separate encoders: reuse compatible rendition pipelines and require permits for newly distinct video encodes.
5. Enforce provider connection counts, separate authorized viewer leases and FFmpeg job quotas. Release an individual viewer's lease on disconnect without affecting the other consumers; close upstream after the last viewer has left and any bounded idle grace expires. New viewers join live, without timeshift. Never leak provider credentials or shared segments to unauthorized viewers.

### 7.3 Custom 24/7 live streams

1. Determine absolute station clock `now`, schedule version and currently airing `ScheduleEntry`.
2. Calculate playback offset from the authoritative current UTC time (`now - startUtc + mediaOffsetMs`) and validate actual playable duration boundaries.
3. Obtain an authorized Plex stream of the selected media item, seeking as needed.
4. Serve a continuous browser-compatible live stream, creating HLS segments only for active viewers or a shared active channel pipeline.
5. At a program boundary, switch to next schedule item without requiring a new client page and update guide/now-playing state.
6. If source fails or stream codec cannot be normalized promptly, use an explicit fallback slate or skip to a valid entry while preserving channel time.
7. Use a distinct `custom_linear` stream-session context that never reports watched/progress events to Plex, including at natural file completion and during viewer-local delayed playback. Verify actual upstream Plex history state, not just app HTTP calls.

**Key engineering risk:** Program joins mid-item, seamless cross-item playback, and segment boundaries are harder than catalog browsing. Build a dedicated prototype before promising production-quality virtual channels. Do not assume merely concatenating file URLs will work across different codecs or media durations.

## 8. Scheduler Rules and Semantics

### 8.1 Authoritative clock model (CONFIRMED)

A custom channel is a **broadcast schedule**, not a long-running video player.

- The Linux server's current UTC clock is the authoritative source of playback position. The clock should be synchronized using standard OS time synchronization (e.g., systemd-timesyncd or chrony).
- Generate and persist broadcast entries with half-open time intervals `[startUtc, endUtc)`, including a Plex media ID and optional in-file start offset.
- Resolve the currently airing entry with `entry.startUtc <= nowUtc < entry.endUtc`.
- Derive position inside the source media as `entry.mediaOffsetMs + (nowUtc - entry.startUtc)`; account for real startup/encoder latency, keyframe seeking and buffer delay during stream initialization.
- **Example:** Episode A starts at 8:00 PM. At 8:12 PM, a newly connected viewer starts about twelve minutes into Episode A. If Episode B began at 8:30 PM, tuning at 8:32 PM starts about two minutes into Episode B.
- No viewers at all: the schedule still advances. A service restart at 8:32 PM must resolve Episode B at minute two, without trying to replay Episode A to catch up.
- Two users joining near the same time must converge on the same **broadcast position**, allowing for measured buffering and HLS segment latency.
- An active shared stream may fan out to many watchers, but every **new tune-in** should reach the **current live edge** rather than replay the stream from its beginning. Returning from a viewer-local pause uses that viewer's buffered timeline until **Go Live** is chosen.
- Persist timelines for EPG and audit/debugging. Video segments are created and retained only for active watchers and eligible paused sessions, not for every second of every idle virtual channel.

### 8.2 Initial channel programming (CONFIRMED)

**MVP channel model:** one channel holds an **application-owned**, admin-authored ordered sequence of **Plex media items** that plays in order and repeats forever. Creation and editing take place entirely in the app's Channel Manager. Plex playlists are neither input sources nor objects that this editor creates or modifies. A channel is not dependent on a running transcoder or an individual viewer.

- **In-app media selection:** navigate/search the configured Plex Movies and TV libraries from an integrated picker; select movies, shows, seasons or episodes without leaving the editor.
- **Manually ordered app playlist:** display each selected movie/episode as a program entry; support intentional repeated entries, deletion, drag-and-drop reorder and keyboard movement; preserve the published order exactly.
- **Source separation:** Plex supplies identity, metadata/artwork and playable content. The app owns all channel definitions, programming lists and scheduling decisions; do not create Plex playlists or depend on existing ones.
- **Add a season:** expand episodes in ascending season/episode index, with explicit handling for specials and items without episode numbers. **PROPOSED:** exclude specials by default with an opt-in.
- **Add a show:** expand seasons from earliest to latest, then each episode in order. An admin can reorder the resulting entries or remove unwanted episodes.
- **New episodes arriving later (CONFIRMED):** Each show selection has a saved **Automatically add new episodes** switch, independent of other shows/channels. An enabled show tracks newly playable Plex episodes and inserts them in that show's season/episode order in the app's program list; an explicitly selected season tracks only that season. Disabled selections stay as authored. **PROPOSED:** default new show selections to Off until the administrator opts in.
- **Preserve curation:** If a show's episodes remain a contiguous natural-order group, insert a new episode into its chronological place inside that group. If the admin manually interleaves that show with other programming or changes its episode order, preserve all existing positions and append each new episode immediately after the last current entry from that source selection, with the insertion recorded in the editor. Never silently reorder unrelated programs or existing episodes. Once the admin manually removes an episode, keep an exclusion so an automated rescan will not restore it.
- **Auto-publish future only:** Auto-add changes may publish without an extra admin click but activate only at the next safe program boundary. Keep the existing on-air entry and enough historical schedule/segments for delayed viewers unchanged; then regenerate the future guide. Partial Plex sync errors must not delete or rewrite a healthy lineup.
- **Loop:** after the final scheduled media entry, play the first item again immediately. No silent blank hour or reset of the viewer's position.
- **Durations:** use verified playable media durations; if metadata is wrong or a file is removed, show an admin warning and use a deterministic fallback policy.
- **Anchor:** schedule has an effective UTC start timestamp. For simple loops with total cycle duration `D`, position at time `t` is `(t - anchorUtc) mod D` for `t >= anchorUtc`, resolved to the playlist entry containing that offset. Persist the anchor and published playlist version so all viewers agree.
- **Edit behavior (CONFIRMED):** Editing builds a draft; the admin previews it and publishes a new version effective at the next existing on-air program boundary. Keep the currently airing episode/movie unchanged until it finishes. If that exact ordered playlist-entry occurrence still exists in the revised list, start the entry **after it** at the boundary, wrapping if needed. If the occurrence was removed, start the **first** revised entry. Admin preview and future guide show the resolved next program.

**Later only:** weighted/random shuffle, multiple show's interleaved episode rotations, calendar blocks, fixed-time shows, commercials/fillers, audience-personalized schedules and external player exports. The code may permit future strategies, but the MVP UI must not expose unfinished options.

### 8.2.1 Channel Manager workflow and UI (CONFIRMED)

1. **Create:** In the app's admin-only **Channels → Manage Channels**, select **Create Channel**. Set channel name, unique guide number, optional artwork/logo and description.
2. **Browse Plex:** Open the built-in content picker. Switch between Movies and Shows. Search by title, filter by library and browse TV seasons/episodes. The picker reads Plex metadata and permitted playable item IDs but never lists Plex playlists as channel sources.
3. **Add programs:** Add movies, a whole TV show, a season or individual episodes. Whole-show/season selections expand into visible playable episode entries in natural order. For each selected show, provide an **Automatically add new episodes** toggle with current state and sync status; a selected season, if enabled, is limited to that season. Track the originating Plex show/season as a durable app-owned source selection, not a Plex playlist.
4. **Arrange:** Reorder entries, remove selected entries, confirm intentional duplicates and see the resulting runtime. Show metadata resolution errors before publication. Save an editable draft without affecting the currently published lineup.
5. **Preview & publish:** Preview the projected guide and schedule. On an existing live channel, the Publish action stages an immutable version, displays the exact next-program handoff time, and states **what plays next**. Locate the current airing playlist occurrence in the revised order: if retained, play its new successor; if removed, play entry one. Show a clear fallback indicator. The current movie/episode stays unchanged; the pending-update badge and future guide reflect the same next title and UTC cutover. New channels use the initial anchor procedure.
6. **Edit later / auto sync:** Re-enter the same in-app editor to change a show toggle, remove or exclude episodes, inspect additions and sync errors, or reorder/republish drafts. Enabled shows are refreshed automatically and their eligible new episodes appear in an atomic future program revision. Neither Plex playlists nor Plex collections are altered.

**Design boundaries:** The IPTV source importer still accepts provider M3U playlists; this is unrelated to Plex playlists. Channel programming is a separate application-owned database concept. Only signed-in Plex-authorized **administrators** can enter the channel editor and publish. A normal viewer sees the resulting channels in Live TV but never the editing controls.

### 8.3 Schedule generation and publishing

- Generate a rolling future horizon (**PROPOSED** seven days) in absolute UTC, and preserve a smaller recent-history window.
- Use immutable published playlist versions and an anchor timestamp; no randomization or per-user ordering is required at launch.
- Persist enough information to reconstruct the active broadcast slot after application/server restart.
- Use accurate playable durations (not merely approximate episode metadata) and explicitly count bumpers/filler.
- Reconcile media removals, inaccessible entries and duration changes without silently moving the live position of all currently scheduled content.
- Make scheduling edits atomic; validate/preview a draft and publish it as a **pending immutable revision effective at the next end of the current episode/movie** for an already-running channel. Determine the first new program as the successor of the retained on-air playlist-entry occurrence in the newly ordered list, or the first new entry if the on-air occurrence was removed. Persist its stable entry ID and the exact UTC handoff, and update only future EPG entries; initial channel publication uses its initial anchor. If two edits are published before cutover, the latest valid admin-confirmed revision supersedes the older pending edit and recomputes the successor without creating a second cutover.
- Display guide times in the viewer's selected timezone while storing UTC; correctly handle DST transitions.
- Use explicit slates or deterministic alternative entries if the current Plex file cannot be played.

### 8.4 Active stream boundary behavior

- Start an eligible Plex media session at the calculated source offset, negotiating compatible direct stream/remux or **permitted CPU-only** transcode behavior. **4K HEVC video encoding is prohibited** even if a transition or timeshift seek would be more convenient with an encode.
- At a program boundary, switch to the next entry **automatically** in the same channel playback session, emitting HLS discontinuity/timestamp signaling and normalizing codecs **only when allowed by the source-specific transcoding policy**. Incompatible 4K HEVC transitions must be rejected/flagged for safe fallback, not solved by prohibited video re-encoding.
- Recheck access at source changes even though the known viewers currently share full Movies and TV library access. If a user's access is revoked, stop their protected playback and show an authorization error with a path to return to Live TV; do not expose the content or mutate the shared schedule for everyone else. No per-user replacement broadcast or slate is needed for normal MVP operation.
- If startup misses the live position, prefer reconciling to the authoritative broadcast clock rather than making the channel permanently late.
- **CONFIRMED:** viewer-local Pause/Resume/Go Live are required for custom channels. At every program boundary, preserve the buffered delayed timeline for paused viewers while continuously generating the authoritative live broadcast for other viewers. Restart-program, arbitrary rewind, seek-back, recording and external IPTV timeshift are out of scope for MVP; no local action can change the shared station clock.

### 8.5 Nonblocking scheduler defaults and engineering bounds

- **Nonblocking implementation default:** Offer Start Now and an optional administrator-selected future anchor time; schedule activation honors the existing safe-boundary rules and authoritative UTC clock. This can be validated during UI implementation without another feature decision.
- **CONFIRMED:** Existing Plex playlists are **not imported**. All custom channel authoring and storage remain in this application.

- Pause retention is **CONFIRMED** as an administrator-editable server-wide setting, with a default of **30 minutes**. A maximum selectable range and disk quota sizing remain implementation details (**PROPOSED:** validate 5–120 minutes and enforce a separate configurable or safe-fixed disk cap).

### 8.6 Viewer-local Pause/Resume/Go Live: engineering contract (CONFIRMED)

**Separate two clocks:** `broadcastNowUtc` always advances for the channel; `viewerCursorUtc` is one viewer's selected point in the broadcast timeline. After Pause, the cursor remains at the paused position while `broadcastNowUtc` advances. After Resume, the viewer cursor advances normally but stays behind the live edge until Go Live is clicked.

**Expected state transitions:**

```text
TUNE_IN -------------------------> LIVE
LIVE -- Pause -------------------> PAUSED (pin viewerCursorUtc)
PAUSED -- Resume ---------------> PLAYING_DELAYED
PLAYING_DELAYED -- Pause -------> PAUSED
PAUSED or PLAYING_DELAYED
     -- Go Live -----------------> LIVE (fresh broadcast clock join)
LIVE or PAUSED or PLAYING_DELAYED
     -- Leave channel ----------> STOPPED (release viewer buffer lease)
PAUSED or PLAYING_DELAYED
     -- Buffer not available ---> EXPIRED (inform viewer; offer Go Live)
```

- On Pause, record the **presentation time being displayed**, not just the time a button was clicked. Account for segment and player buffering when mapping the current media PTS to broadcast UTC.
- On Resume, continue from that paused cursor. If the source changes from Episode A to Episode B while paused, retained segments and HLS discontinuity metadata must allow the viewer to finish A and then see B while the station itself runs further ahead.
- The playback service should distinguish a channel's canonical live pipeline from the authorized viewer-specific session/manifest. Segment cache can be shared among viewers of the same station, but playback cursors and permissions **cannot** be shared.
- During active watch or a valid pause lease, maintain a bounded time-indexed rolling segment store for the channel; do **not** require one separate transcoding job per paused viewer. Use an authenticated per-session manifest/path with segment references and proper start/stop/discontinuity handling.
- On **Go Live**, stop referencing old segments, clear the delayed state, resolve the current schedule entry and media offset, and seek to/reconnect near the live edge. This should work even if a different movie/episode is on air.
- An ordinary **Resume** must not suddenly snap to live. A stale or exhausted buffer must produce `EXPIRED` with a visible explanatory message, not silence, indefinite spinner, or playback of unrelated video.
- Protect segments against unauthorized read: verify app session/Plex media permission and resource ownership on every manifest and media access. Shared segment caching is permitted because all intended users currently have TV and Movies grants, but a revoked or differently restricted user must be denied or isolated appropriately. Do not put permanent upstream tokens in playlist URLs.
- On reload/browser disconnect, time out the pause lease and clean up resources. Restoring a paused channel session after full page reload is **LATER/OPEN**. In-memory video state survives only while the session remains valid.
- Keep external IPTV live-only. An IPTV player must not inherit the custom channel buffer, state machine, or DVR controls.
- **CONFIRMED:** `customChannels.pauseRetentionMinutes` is a persisted admin-only server setting, defaulting to `30`. It controls the **maximum behind-live delay** that can be served from retained content, including after Resume. Every custom channel uses this global value; individual viewers cannot override it. IPTV channels do not use this setting.
- **PROPOSED validation:** Accept whole minutes from 5 through 120 inclusive; reject invalid, negative, NaN or unreasonable inputs at both UI and API layers. These bounds are engineering guardrails, not a user-approved preference range and can be refined after server hardware testing.
- **Persistence:** Store the setting in a versioned application settings record in SQLite and load it before starting playback workers. A fresh install and a migration with no existing value both use 30. No system restart should be needed after a valid update.
- **Runtime behavior:** A successful admin change applies to all custom-channel sessions as soon as persisted. Existing viewers outside a newly reduced window enter `EXPIRED` with a clear reason and **Go Live** button; warn the admin before reducing the limit. Increasing the setting cannot recover segments already evicted. Changes never alter channel programming schedules or other viewers' live state.
- **Capacity protection:** A duration limit is not a guarantee of continuous video availability. Apply independent segment-cache quotas, free-space floors, lease expiry, cache reclamation, and FFmpeg concurrency limits. Show an admin-visible effective retention and a storage-pressure warning when actual buffered availability is shorter than configured.
- **Capacity estimate:** At constant 8 Mbps, 30 minutes is approximately 1.8 GB per active buffered channel before filesystem/HLS overhead, not automatically per viewer; shared stream caching may avoid unnecessary duplicates, but access-control partitions can increase usage. Profile actual output bitrates and simultaneous paused sessions before sizing quotas.
- **Precise expiration:** While `broadcastNowUtc - viewerCursorUtc` exceeds the effective available buffer duration (or the cursor's referenced segments are missing), transition the viewer to `EXPIRED`; do not silently play from the earliest remaining segment. A delayed session 5 minutes behind live may remain delayed while playing, as long as its cursor remains available. On **Go Live**, clear the expired state and rejoin the current broadcast slot.

**Suggested endpoint additions** (illustrative, session-authenticated; playback token never in log/query parameters): `GET /api/v1/admin/settings/custom-channel-playback` and `PATCH /api/v1/admin/settings/custom-channel-playback` (admin only; JSON property `pauseRetentionMinutes`), plus `POST /api/v1/playback/sessions/:id/pause`, `POST /api/v1/playback/sessions/:id/resume`, `POST /api/v1/playback/sessions/:id/go-live`, `GET /api/v1/playback/sessions/:id/state` (returns `state`, `viewerCursorUtc`, `broadcastNowUtc`, `behindLiveMs`, `bufferStartUtc`, `bufferEndUtc`). Prefer serializable, idempotent transitions; handle overlap/races and stale sessions.

**Performance/testing considerations:** Test with mixed codec source transitions, HLS segment expiry, 2+ viewers on the same station (one paused, one live), Plex per-user access rules, page sleep/disconnect, host reboot, disk pressure, and abrupt media removal. Simulated clock tests must prove that Pause has zero effect on EPG or other viewers.

## 10. Security and Privacy Requirements

- HTTPS is mandatory for remote use; use secure, HttpOnly, SameSite cookies, CSRF protection and strict allowed redirects for Plex-account linking.
- All browser users authenticate via Plex. Validate access to the configured Plex server in addition to Plex login; authorize every catalog, artwork, write and playback endpoint.
- Encrypt Plex tokens and M3U credentials/secret headers at rest with a Linux host-managed encryption key; support rotation and revocation.
- Restrict proxy and FFmpeg input sources to approved provider/server origins; protect against SSRF, redirect abuse, DNS rebinding and access to internal admin endpoints. Explicitly allow configured LAN Plex addresses without introducing an arbitrary URL fetch endpoint.
- Validate uploaded M3U/XMLTV sizes, timeouts, text encoding and XML parsing safety; set source and refresh limits.
- Rate-limit logins, auth PIN polling, source refreshes and playback session creation.
- Do not log access tokens, IPTV account passwords or signed stream URLs.
- Bound stream concurrency, FFmpeg processes, disk segment cache, memory and network bandwidth. Admin-configured pause retention cannot override a storage safety limit or circumvent individual viewer media permissions.
- Keep Plex server, streaming worker and admin control endpoints private. The owner's existing reverse proxy provides public HTTPS; protect the internal HTTP app port from unsolicited external access. Trust forwarded headers only from explicitly configured proxies and reject unsafe external origins/redirects.
- Document authorized-use assumptions for personal Plex libraries and legally supplied IPTV streams.
- Provide native Linux service isolation (non-root `systemd` user), restrictive file permissions and documented secrets, backups, logs and updates.
- Include backup/restore for settings, source mappings and custom channel schedule definitions, excluding plaintext secrets.
